01.4.2

Cuentas Bancarias Institucionales (Cuentas Ordenantes)

Catálogo maestro único del padrón de cuentas bancarias productivas y operativas del Poder Judicial del Estado de Veracruz para la recepción de fondos y la dispersión electrónica vía transferencias bancarias (SPEI / SPID), vinculadas unívocamente al Plan de Cuentas CONAC (1.1.1.2).

Modo B — Catálogo Central de Tesorería Tipo: Análisis Funcional y Modelo de Datos (DOC-08) Normativa: Art. 67 LGCG (Pago Electrónico Obligatorio)
🏛️ Marco Jurídico: Extinción del Cheque y Obligatoriedad de Transferencias Electrónicas

Conforme al Artículo 67 de la Ley General de Contabilidad Gubernamental (LGCG) y los lineamientos de la Ley de Disciplina Financiera: «Los pagos que tengan que hacer con cargo a sus respectivos presupuestos los entes públicos federales, estatales y municipales se efectuarán en forma electrónica, mediante abono en cuenta de los beneficiarios...».

Por disposición legal, el SIAF-PJEV no opera bajo esquemas de chequeras físicas como eje transaccional, sino bajo Transferencias Electrónicas Interbancarias (SPEI / Dispersión Bancaria) con validación obligatoria de CLABE de 18 dígitos y generación de comprobantes con clave de rastreo Banxico / folio CEP.

1 Descripción General

El catálogo 01.4.2 Cuentas Bancarias Institucionales constituye el padrón maestro centralizado de las cuentas de cheques e inversión aperturadas a nombre del Poder Judicial del Estado de Veracruz / Consejo de la Judicatura en las instituciones del Sistema Financiero Mexicano autorizadas (BBVA México, Banorte, Santander, etc.).

Este catálogo actúa como la fuente única de verdad para todos los subsistemas del SIAF-PJEV:

  • Subsistema de Ingresos (04): Alimenta las cuentas recaudadoras receptoras de ministraciones de SEFIPLAN, aranceles del Fondo Auxiliar y depósitos en juzgados.
  • Subsistema de Cuentas por Pagar y Tesorería (05 / 06): Define las cuentas ordenantes pagadoras desde las cuales se instruyen las transferencias electrónicas a proveedores, contratistas, comisionados y nómina.
  • Subsistema de Contabilidad (03): Garantiza la cuadratura contable y la conciliación bancaria mensual automatizada en la subcuenta de activo 1.1.1.2 Bancos / Tesorería.
2 Objetivo y Alcance

Objetivo: Administrar y parametrizar de manera estricta y auditable las cuentas bancarias institucionales del PJEV, asegurando la integridad de las transferencias electrónicas de egresos, la correcta recepción de depósitos de ingresos, el etiquetado por fuente de financiamiento y el enlace contable 1:1 con el Plan de Cuentas CONAC.

Dentro del Alcance Fuera del Alcance
  • Padrón institucional maestro de cuentas bancarias ordenantes del PJEV.
  • Validación sintáctica y aritmética del dígito verificador de la CLABE (18 dígitos).
  • Tipificación del fondo institucional (Ministración Estatal, Fondo Auxiliar, Recursos Propios, Juzgados, Fondos Federales FASP).
  • Enlace contable inmutable a subcuentas de la clase 1.1.1.2 Bancos / Tesorería.
  • Parametrización de convenios de cobranza (CIE / Concentradores).
  • Control de capacidades operativas: es_recaudadora y es_pagadora.
  • Protección contra borrado físico (soft-delete) e inmutabilidad con movimientos.
  • Talonarios y emisión física masiva de cheques (reemplazados por transferencias electrónicas SPEI Art. 67 LGCG).
  • Registro de cuentas de terceros/beneficiarios (se realiza en el padrón de proveedores 01.3.1 o empleados 01.3.3).
  • Cálculo de la conciliación bancaria mensual (se efectúa en 03.3.2).

6 Procedimientos Almacenados (Stored Procedures PostgreSQL)

Gobernanza transaccional en PostgreSQL bajo convención SECURITY DEFINER, SET search_path y respuesta estándar JSONB.

6.1. Procedimiento LEER (config.fn_leer_cuentas_bancarias)

CREATE OR REPLACE FUNCTION config.fn_leer_cuentas_bancarias(
    p_usuario VARCHAR,
    p_tipo_fondo VARCHAR DEFAULT NULL,
    p_solo_recaudadoras BOOLEAN DEFAULT FALSE,
    p_solo_pagadoras BOOLEAN DEFAULT FALSE,
    p_solo_activos BOOLEAN DEFAULT TRUE
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = config, contabilidad, public
AS $$
DECLARE
    v_data JSONB;
BEGIN
    SELECT jsonb_agg(
        jsonb_build_object(
            'cuenta_bancaria_id', cb.cuenta_bancaria_id,
            'banco_id', cb.banco_id,
            'institucion_bancaria', cb.institucion_bancaria,
            'numero_cuenta', cb.numero_cuenta,
            'clabe_interbancaria', cb.clabe_interbancaria,
            'sucursal', cb.sucursal,
            'convenio_cie', cb.convenio_cie,
            'nombre_identificador', cb.nombre_identificador,
            'tipo_fondo', cb.tipo_fondo,
            'cuenta_contable_id', cb.cuenta_contable_id,
            'cuenta_contable_clave', cc.clave,
            'cuenta_contable_desc', cc.nombre,
            'es_recaudadora', cb.es_recaudadora,
            'es_pagadora', cb.es_pagadora,
            'saldo_inicial', cb.saldo_inicial,
            'estatus_registro', cb.estatus_registro
        ) ORDER BY cb.cuenta_bancaria_id
    )
    INTO v_data
    FROM config.cat_cuentas_bancarias cb
    LEFT JOIN contabilidad.cat_cuentas cc ON cc.cuenta_id = cb.cuenta_contable_id
    WHERE (NOT p_solo_activos OR cb.estatus_registro = 1)
      AND (p_tipo_fondo IS NULL OR cb.tipo_fondo = p_tipo_fondo)
      AND (NOT p_solo_recaudadoras OR cb.es_recaudadora = TRUE)
      AND (NOT p_solo_pagadoras OR cb.es_pagadora = TRUE);

    RETURN jsonb_build_object(
        'error', 0,
        'mensaje', 'Padrón de cuentas bancarias recuperado exitosamente.',
        'data', COALESCE(v_data, '[]'::jsonb)
    );
EXCEPTION WHEN OTHERS THEN
    RETURN jsonb_build_object('error', -2, 'mensaje', 'Error al consultar cuentas bancarias: ' || SQLERRM, 'data', NULL);
END;
$$;

6.2. Procedimiento CRUD (config.fn_crud_cuentas_bancarias)

CREATE OR REPLACE FUNCTION config.fn_crud_cuentas_bancarias(
    p_accion VARCHAR,
    p_usuario VARCHAR,
    p_payload JSONB
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = config, contabilidad, public
AS $$
DECLARE
    v_id BIGINT;
    v_banco_id BIGINT;
    v_banco_nom VARCHAR;
    v_cuenta VARCHAR;
    v_clabe VARCHAR;
    v_cta_contable_id BIGINT;
BEGIN
    IF p_accion = 'CREAR' THEN
        v_banco_id        := (p_payload->>'banco_id')::BIGINT;
        v_banco_nom       := TRIM(p_payload->>'institucion_bancaria');
        v_cuenta          := TRIM(p_payload->>'numero_cuenta');
        v_clabe           := TRIM(p_payload->>'clabe_interbancaria');
        v_cta_contable_id := (p_payload->>'cuenta_contable_id')::BIGINT;

        -- 1. Validación de 18 dígitos en CLABE
        IF length(v_clabe) != 18 OR v_clabe !~ '^[0-9]+$' THEN
            RETURN jsonb_build_object('error', -1, 'mensaje', 'La CLABE interbancaria debe contener exactamente 18 dígitos numéricos.');
        END IF;

        -- 2. Unicidad de cuenta bancaria en la misma entidad financiera
        IF EXISTS (
            SELECT 1 FROM config.cat_cuentas_bancarias
            WHERE (banco_id = v_banco_id OR institucion_bancaria = v_banco_nom)
              AND numero_cuenta = v_cuenta
              AND estatus_registro = 1
        ) THEN
            RETURN jsonb_build_object('error', -1, 'mensaje', 'Ya existe una cuenta activa registrada con ese número para la institución bancaria.');
        END IF;

        -- 3. Validación de enlace contable obligatorio a 1.1.1.2 (Bancos / Tesorería)
        IF NOT EXISTS (
            SELECT 1 FROM contabilidad.cat_cuentas
            WHERE cuenta_id = v_cta_contable_id
              AND clave LIKE '1.1.1.2%'
        ) THEN
            RETURN jsonb_build_object('error', -1, 'mensaje', 'La cuenta contable debe pertenecer obligatoriamente a la clase 1.1.1.2 (Bancos / Tesorería).');
        END IF;

        INSERT INTO config.cat_cuentas_bancarias (
            banco_id, institucion_bancaria, numero_cuenta, clabe_interbancaria, sucursal,
            convenio_cie, nombre_identificador, tipo_fondo, cuenta_contable_id,
            es_recaudadora, es_pagadora, saldo_inicial, estatus_registro,
            usuario_c, fecha_c
        ) VALUES (
            v_banco_id, v_banco_nom, v_cuenta, v_clabe, TRIM(p_payload->>'sucursal'),
            TRIM(p_payload->>'convenio_cie'), TRIM(p_payload->>'nombre_identificador'),
            p_payload->>'tipo_fondo', v_cta_contable_id,
            COALESCE((p_payload->>'es_recaudadora')::BOOLEAN, TRUE),
            COALESCE((p_payload->>'es_pagadora')::BOOLEAN, TRUE),
            COALESCE((p_payload->>'saldo_inicial')::NUMERIC, 0.00),
            1, p_usuario, CURRENT_TIMESTAMP
        ) RETURNING cuenta_bancaria_id INTO v_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Cuenta bancaria institucional registrada exitosamente.', 'data', jsonb_build_object('cuenta_bancaria_id', v_id));

    ELSIF p_accion = 'EDITAR' THEN
        v_id := (p_payload->>'cuenta_bancaria_id')::BIGINT;
        v_clabe := TRIM(p_payload->>'clabe_interbancaria');

        IF length(v_clabe) != 18 OR v_clabe !~ '^[0-9]+$' THEN
            RETURN jsonb_build_object('error', -1, 'mensaje', 'La CLABE interbancaria debe contener exactamente 18 dígitos numéricos.');
        END IF;

        UPDATE config.cat_cuentas_bancarias SET
            sucursal             = TRIM(p_payload->>'sucursal'),
            convenio_cie         = TRIM(p_payload->>'convenio_cie'),
            nombre_identificador = TRIM(p_payload->>'nombre_identificador'),
            es_recaudadora       = (p_payload->>'es_recaudadora')::BOOLEAN,
            es_pagadora          = (p_payload->>'es_pagadora')::BOOLEAN,
            usuario_m            = p_usuario,
            fecha_m              = CURRENT_TIMESTAMP
        WHERE cuenta_bancaria_id = v_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Cuenta bancaria actualizada correctamente.', 'data', jsonb_build_object('cuenta_bancaria_id', v_id));

    ELSIF p_accion = 'CAMBIAR_ESTATUS' THEN
        v_id := (p_payload->>'cuenta_bancaria_id')::BIGINT;

        -- Protección: No inactivar si existen transferencias u operaciones en tránsito en el ejercicio
        IF (p_payload->>'estatus_registro')::SMALLINT = 0 THEN
            IF EXISTS (
                SELECT 1 FROM cxp.cxp_ordenes_pago
                WHERE cuenta_bancaria_origen_id = v_id
                  AND estado_orden NOT IN ('CANCELADA', 'PAGADA')
            ) OR EXISTS (
                SELECT 1 FROM ingresos.ing_ingresos
                WHERE cuenta_bancaria_id = v_id
                  AND estado_ingreso NOT IN ('CANCELADO')
            ) THEN
                RETURN jsonb_build_object('error', -1, 'mensaje', 'No se puede inactivar una cuenta bancaria con operaciones activas en trámite.');
            END IF;
        END IF;

        UPDATE config.cat_cuentas_bancarias SET
            estatus_registro = (p_payload->>'estatus_registro')::SMALLINT,
            usuario_m        = p_usuario,
            fecha_m          = CURRENT_TIMESTAMP
        WHERE cuenta_bancaria_id = v_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Estatus de la cuenta bancaria modificado.', 'data', jsonb_build_object('cuenta_bancaria_id', v_id));
    END IF;

    RETURN jsonb_build_object('error', -1, 'mensaje', 'Acción no soportada: ' || p_accion, 'data', NULL);
END;
$$;

// NestJS Controller: CuentasBancariasController
@ApiTags('01.4.2 Cuentas Bancarias Institucionales')
@Controller('api/v1/config/cuentas-bancarias')
@UseGuards(JwtAuthGuard, RolesGuard)
export class CuentasBancariasController {
  constructor(private readonly service: CuentasBancariasService) {}

  @Get()
  @ApiOperation({ summary: 'Listar cuentas bancarias institucionales activas' })
  async listar(
    @Query('tipo_fondo') tipoFondo?: string,
    @Query('solo_recaudadoras') soloRecaudadoras?: boolean,
    @Query('solo_pagadoras') soloPagadoras?: boolean,
    @CurrentUser() user: UserSession
  ) {
    return this.service.leerCuentas(user.username, tipoFondo, soloRecaudadoras, soloPagadoras);
  }

  @Post()
  @ApiOperation({ summary: 'Registrar nueva cuenta bancaria institucional' })
  async crear(@Body() dto: CreateCuentaBancariaDto, @CurrentUser() user: UserSession) {
    return this.service.crudCuenta('CREAR', user.username, dto);
  }

  @Put(':id')
  @ApiOperation({ summary: 'Actualizar datos operativos de la cuenta bancaria' })
  async actualizar(
    @Param('id', ParseIntPipe) id: number,
    @Body() dto: UpdateCuentaBancariaDto,
    @CurrentUser() user: UserSession
  ) {
    return this.service.crudCuenta('EDITAR', user.username, { ...dto, cuenta_bancaria_id: id });
  }

  @Patch(':id/estatus')
  @ApiOperation({ summary: 'Modificar estatus de la cuenta bancaria (Baja lógica)' })
  async cambiarEstatus(
    @Param('id', ParseIntPipe) id: number,
    @Body() dto: CambiarEstatusDto,
    @CurrentUser() user: UserSession
  ) {
    return this.service.crudCuenta('CAMBIAR_ESTATUS', user.username, { ...dto, cuenta_bancaria_id: id });
  }
}
8 Reglas de Negocio Institucionales
CódigoReglaDescripción Operativa
RN-CTA-01 Obligatoriedad de Transferencias SPEI (Art. 67 LGCG) Todo egreso institucional se instruye electrónicamente con abono en cuenta bancaria del beneficiario. El catálogo de cuentas administra las cuentas ordenantes emisoras del SPEI.
RN-CTA-02 Validación Estricta de 18 Dígitos en CLABE Toda cuenta bancaria debe registrar una CLABE Interbancaria de exactamente 18 dígitos puramente numéricos.
RN-CTA-03 Enlace Contable Inmutable al COA (Clase 1.1.1.2) El campo cuenta_contable_id es forzoso y debe vincularse a una subcuenta de activo de la clase 1.1.1.2 Bancos / Tesorería.
RN-CTA-04 No Mezcla de Fondos Institucionales Las cuentas bancarias se etiquetan por su fondo de destino (Ministración, Fondo Auxiliar, Depósitos Judiciales, Federal). El sistema impide pagos cruzados entre fondos no autorizados.
RN-CTA-05 Protección Referencial contra Baja Lógica El SP rechaza la inactivación de una cuenta bancaria si existen órdenes de pago o depósitos vigentes en trámite durante el ejercicio fiscal activo.
