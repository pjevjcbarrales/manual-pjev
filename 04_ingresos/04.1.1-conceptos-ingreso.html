04.1.1

Tipos y Subtipos de Trámite de Ingreso

Catálogo institucional rector que parametriza las 4 macro-familias y 12 procedimientos operativos de ingreso. Alimenta el Asistente Visual (Wizard) del registro, autoconfigurando los requerimientos de captura, la contraparte, el CRI normativo y la pre-póliza en la Matriz de Conversión CONAC.

Pendiente de desarrollo Análisis funcional canónico (DOC-08) Responsable: Eunice Alineado con Egresos (05.2.1)
📌 Principio de Diseño: Homogeneidad con Cuentas por Pagar (Egresos 05.2.1)

1. Experiencia de Usuario Centrada en Trámites: Al igual que en Egresos el usuario clasifica su gasto por Tipo de Pago y Subtipo (ej. Nómina, Servicios Básicos, Viáticos), en Ingresos el operador inicia su captura seleccionando el Tipo y Subtipo de Trámite de Ingreso. El usuario no selecciona movimientos contables abstractos; selecciona la operación que tiene en sus manos (Ministración, Rendimiento bancario, Reintegro de viáticos, Renta).

2. Autoconfiguración de Pantalla: La elección del Subtrámite condiciona automáticamente qué campos solicita la interfaz (número de oficio, fecha esperada, depositante o cuenta bancaria) y si exige distribución por capítulos de egreso.

3. Enlace con la Matriz de Conversión: Cada subtipo mapea directamente hacia el Clasificador por Rubro de Ingresos (CRI 01.2.7) y hacia la Matriz de Conversión Oficial (03.1.2), permitiendo calcular la Pre-póliza contable en vivo desde el Modo Borrador.

1 Descripción General

El catálogo 04.1.1 Tipos y Subtipos de Trámite de Ingreso constituye el marco operativo y clasificatorio del subsistema de ingresos del Poder Judicial del Estado de Veracruz. Reemplaza cualquier lista plana desarticulada por un esquema estructurado en 4 Macro-familias que agrupan 12 Subtipos o Procedimientos Canónicos.

Cada subtipo funciona como una plantilla de comportamiento transaccional que le indica al sistema:

  • Si la operación es Presupuestaria (afecta la Ley de Ingresos en cuentas 8.1.x y rubros CRI) o Extrapresupuestaria (afecta exclusivamente balance patrimonial en pasivos de custodia 2.1.9).
  • El tipo de contraparte o depositante requerido (Ente Público como SEFIPLAN, Entidad Bancaria, Empleado Judicial o Arrendatario).
  • Si nace como Ingreso Esperado / Devengado (requiere oficio y control de saldo por recaudar en parcialidades) o como Ingreso Simultáneo en Firme (percepción directa en cuentas bancarias productivas).
  • Qué regla de la Matriz de Conversión (03.1.2) debe ejecutarse para generar la Pre-póliza en modo borrador y el asiento definitivo.
2 Objetivo y Alcance

Objetivo: Estandarizar la tramitología de ingresos del PJEV, guiando al usuario mediante un asistente visual claro y garantizando la vinculación automática con el CRI y las matrices contables CONAC desde el momento en que se inicia la captura en borrador.

Dentro del Alcance Fuera del Alcance (Exclusiones)
  • Padrón institucional de 4 tipos y 12 subtipos de trámite parametrizados.
  • Alimentación directa del Asistente Visual (Wizard Modal) en 04.2.1.
  • Asociación a clave CRI (01.2.7) y fuente predeterminada (01.2.4).
  • Banderas de comportamiento de captura (oficio, cuenta bancaria, desglose de capítulos).

5 Procedimientos Almacenados (Stored Procedures)

Gobernanza transaccional en PostgreSQL bajo convención SECURITY DEFINER, SET search_path y respuesta estándar JSONB { "error": 0, "mensaje": "OK", "data": [...] }.

5.1. Procedimiento LEER (ingresos.fn_leer_subtipos_tramite)

CREATE OR REPLACE FUNCTION ingresos.fn_leer_subtipos_tramite(
    p_usuario VARCHAR,
    p_tipo_principal VARCHAR DEFAULT NULL,
    p_subtipo_id BIGINT DEFAULT NULL,
    p_solo_activos BOOLEAN DEFAULT TRUE
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = ingresos, contabilidad, config, public
AS $$
DECLARE
    v_data JSONB;
BEGIN
    SELECT jsonb_agg(
        jsonb_build_object(
            'subtipo_tramite_id', st.subtipo_tramite_id,
            'tipo_principal', st.tipo_principal,
            'clave_subtipo', st.clave_subtipo,
            'nombre_subtipo', st.nombre_subtipo,
            'descripcion_card', st.descripcion_card,
            'icono_svg', st.icono_svg,
            'tipo_contraparte', st.tipo_contraparte,
            'afecta_presupuesto', st.afecta_presupuesto,
            'momento_inicial', st.momento_inicial,
            'requiere_oficio', st.requiere_oficio,
            'requiere_capitulo', st.requiere_capitulo,
            'requiere_cuenta_bancaria', st.requiere_cuenta_bancaria,
            'cri_id_default', st.cri_id_default,
            'cri_clave', cri.cri_clave,
            'cri_descripcion', cri.cri_descripcion,
            'fuente_id_default', st.fuente_id_default,
            'cff_clave', cff.cff_clave,
            'cff_descripcion', cff.cff_descripcion,
            'mcr_matriz_id', st.mcr_matriz_id,
            'mcv_clave', mcv.mcv_clave,
            'estatus_registro', st.estatus_registro
        ) ORDER BY st.tipo_principal, st.subtipo_tramite_id
    )
    INTO v_data
    FROM ingresos.cat_subtipos_tramite_ingreso st
    LEFT JOIN config.catalogo_cri cri ON cri.cri_id = st.cri_id_default
    LEFT JOIN config.catalogo_fuentes_financiamiento cff ON cff.cff_id = st.fuente_id_default
    LEFT JOIN contabilidad.matriz_conversion mcv ON mcv.mcv_id = st.mcr_matriz_id
    WHERE (p_tipo_principal IS NULL OR st.tipo_principal = p_tipo_principal)
      AND (p_subtipo_id IS NULL OR st.subtipo_tramite_id = p_subtipo_id)
      AND (NOT p_solo_activos OR st.estatus_registro = 1);

    RETURN jsonb_build_object(
        'error', 0,
        'mensaje', 'Subtipos de trámite de ingreso recuperados exitosamente.',
        'data', COALESCE(v_data, '[]'::jsonb)
    );
EXCEPTION WHEN OTHERS THEN
    RETURN jsonb_build_object(
        'error', -2,
        'mensaje', 'Error técnico al consultar subtipos de trámite: ' || SQLERRM,
        'data', NULL
    );
END;
$$;

5.2. Procedimiento CRUD (ingresos.fn_crud_subtipos_tramite)

CREATE OR REPLACE FUNCTION ingresos.fn_crud_subtipos_tramite(
    p_accion VARCHAR,
    p_usuario VARCHAR,
    p_payload JSONB
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = ingresos, config, contabilidad, public
AS $$
DECLARE
    v_id BIGINT;
    v_clave VARCHAR(30);
BEGIN
    IF p_accion = 'CREAR' THEN
        v_clave := UPPER(TRIM(p_payload->>'clave_subtipo'));
        IF EXISTS (SELECT 1 FROM ingresos.cat_subtipos_tramite_ingreso WHERE clave_subtipo = v_clave) THEN
            RETURN jsonb_build_object('error', -1, 'mensaje', 'Ya existe un subtipo con la clave ' || v_clave, 'data', NULL);
        END IF;

        INSERT INTO ingresos.cat_subtipos_tramite_ingreso (
            tipo_principal, clave_subtipo, nombre_subtipo, descripcion_card, icono_svg,
            tipo_contraparte, afecta_presupuesto, momento_inicial, requiere_oficio,
            requiere_capitulo, requiere_cuenta_bancaria, cri_id_default, fuente_id_default,
            mcr_matriz_id, estatus_registro, usuario_c, fecha_c
        ) VALUES (
            p_payload->>'tipo_principal',
            v_clave,
            TRIM(p_payload->>'nombre_subtipo'),
            TRIM(p_payload->>'descripcion_card'),
            COALESCE(p_payload->>'icono_svg', 'file-text'),
            p_payload->>'tipo_contraparte',
            (p_payload->>'afecta_presupuesto')::BOOLEAN,
            p_payload->>'momento_inicial',
            COALESCE((p_payload->>'requiere_oficio')::BOOLEAN, false),
            COALESCE((p_payload->>'requiere_capitulo')::BOOLEAN, false),
            COALESCE((p_payload->>'requiere_cuenta_bancaria')::BOOLEAN, false),
            (p_payload->>'cri_id_default')::BIGINT,
            (p_payload->>'fuente_id_default')::BIGINT,
            (p_payload->>'mcr_matriz_id')::BIGINT,
            1, p_usuario, CURRENT_TIMESTAMP
        ) RETURNING subtipo_tramite_id INTO v_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Subtipo creado exitosamente.', 'data', jsonb_build_object('subtipo_tramite_id', v_id));

    ELSIF p_accion = 'EDITAR' THEN
        v_id := (p_payload->>'subtipo_tramite_id')::BIGINT;
        UPDATE ingresos.cat_subtipos_tramite_ingreso SET
            nombre_subtipo           = TRIM(p_payload->>'nombre_subtipo'),
            descripcion_card         = TRIM(p_payload->>'descripcion_card'),
            icono_svg                = COALESCE(p_payload->>'icono_svg', icono_svg),
            tipo_contraparte         = p_payload->>'tipo_contraparte',
            afecta_presupuesto       = (p_payload->>'afecta_presupuesto')::BOOLEAN,
            momento_inicial          = p_payload->>'momento_inicial',
            requiere_oficio          = (p_payload->>'requiere_oficio')::BOOLEAN,
            requiere_capitulo        = (p_payload->>'requiere_capitulo')::BOOLEAN,
            requiere_cuenta_bancaria = (p_payload->>'requiere_cuenta_bancaria')::BOOLEAN,
            cri_id_default           = (p_payload->>'cri_id_default')::BIGINT,
            fuente_id_default        = (p_payload->>'fuente_id_default')::BIGINT,
            mcr_matriz_id            = (p_payload->>'mcr_matriz_id')::BIGINT,
            usuario_m                = p_usuario,
            fecha_m                  = CURRENT_TIMESTAMP
        WHERE subtipo_tramite_id = v_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Subtipo actualizado exitosamente.', 'data', jsonb_build_object('subtipo_tramite_id', v_id));

    ELSIF p_accion = 'CAMBIAR_ESTATUS' THEN
        v_id := (p_payload->>'subtipo_tramite_id')::BIGINT;
        UPDATE ingresos.cat_subtipos_tramite_ingreso SET
            estatus_registro = (p_payload->>'estatus_registro')::SMALLINT,
            usuario_m        = p_usuario,
            fecha_m          = CURRENT_TIMESTAMP
        WHERE subtipo_tramite_id = v_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Estatus actualizado.', 'data', jsonb_build_object('subtipo_tramite_id', v_id));
    END IF;

    RETURN jsonb_build_object('error', -1, 'mensaje', 'Acción no reconocida: ' || p_accion, 'data', NULL);
END;
$$;

// NestJS Controller: SubtiposTramiteIngresoController
@ApiTags('04.1.1 Tipos y Subtipos de Trámite de Ingreso')
@Controller('api/v1/ingresos/subtipos-tramite')
@UseGuards(JwtAuthGuard, RolesGuard)
export class SubtiposTramiteIngresoController {
  constructor(private readonly service: SubtiposTramiteService) {}

  @Get()
  @ApiOperation({ summary: 'Listar subtipos de trámite de ingreso para el Wizard' })
  async listar(@CurrentUser() user: UserSession, @Query('tipo_principal') tipo?: string) {
    return this.service.leer(user, tipo);
  }

  @Post()
  @ApiOperation({ summary: 'Crear nuevo subtipo institucional' })
  async crear(@CurrentUser() user: UserSession, @Body() dto: CreateSubtipoDto) {
    return this.service.crear(user, dto);
  }

  @Put(':id')
  @ApiOperation({ summary: 'Modificar configuración de subtipo' })
  async actualizar(@Param('id') id: string, @CurrentUser() user: UserSession, @Body() dto: UpdateSubtipoDto) {
    return this.service.actualizar(user, BigInt(id), dto);
  }

  @Patch(':id/estatus')
  @ApiOperation({ summary: 'Baja lógica / Reactivación' })
  async cambiarEstatus(@Param('id') id: string, @CurrentUser() user: UserSession, @Body() dto: EstatusDto) {
    return this.service.cambiarEstatus(user, BigInt(id), dto.estatus_registro);
  }
}
7 Reglas de Negocio del Catálogo
RN-SUB-01 · Obligatoriedad de Matriz CONAC para Subtipos Presupuestarios

Todo subtipo con afecta_presupuesto = true debe contar obligatoriamente con un mcr_matriz_id válido y activo en contabilidad.matriz_conversion (14, 15 o 16). Esto garantiza que la Pre-póliza en Borrador pueda generarse sin excepciones.

RN-SUB-02 · Condicionamiento de Desglose por Capítulos

Los subtipos de la familia MINISTRACIONES deben tener requiere_capitulo = true. La pantalla de registro forzará a que el capturista distribuya el total entre los Capítulos 1000 a 5000 antes de autorizar.

RN-SUB-03 · Protección Histórica e Inmutabilidad

No se permite eliminar físicamente un subtipo de trámite si existen ingresos históricos asociados. La desactivación se realiza exclusivamente mediante estatus_registro = 0.
