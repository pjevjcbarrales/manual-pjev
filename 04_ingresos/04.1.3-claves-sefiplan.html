04.1.3

Claves Presupuestales y Carteras SEFIPLAN

Catálogo de gobernanza presupuestaria que administra la correspondencia entre los Órganos Judiciales (TSJ, TCA, TDJ, OAJ), capítulos de gasto, números de cartera SEFIPLAN, claves programáticas de 11 segmentos y nemotécnicos de Caja para la ministración estatal ordinaria y extraordinaria.

Modo B — Formulario de Configuración Institucional Tipo: Análisis Funcional (DOC-08)
📌 Desacoplamiento de Cadenas SEFIPLAN y Principio KISS

Este catálogo elimina la necesidad de que los analistas o cajeros capturen o memoricen cadenas complejas de 50 dígitos al registrar los movimientos de ministración en el módulo 04.2.1. Al seleccionar el Órgano Judicial y el Capítulo de Gasto, el sistema resuelve automáticamente la Cartera, la Cuenta de Caja (ej. 1 OPE-1, 1 NOM-1) y la Clave Programática de 11 Segmentos.

Gobernanza Anual: Las carteras y codificaciones presupuestarias son fijadas anualmente en el Decreto de Presupuesto de Egresos del Gobierno del Estado por la Secretaría de Finanzas y Planeación (SEFIPLAN). Su parametrización en base de datos asegura que las modificaciones anuales no requieran cambios en el código fuente.

1 Descripción General

El catálogo 04.1.3 Claves Presupuestales y Carteras SEFIPLAN establece el vínculo formal de homologación entre la estructura programática interna del Poder Judicial del Estado de Veracruz (PJEV) y la nomenclatura presupuestaria y de control de ingresos del Poder Ejecutivo del Estado a través de SEFIPLAN.

Cuando el PJEV tramita la ministración quincenal o mensual de recursos estatales, SEFIPLAN emite órdenes de cobro y recibos oficiales de Caja donde fragmenta el importe total en partidas específicas. Cada partida está asignada a un Órgano ejecutor (Tribunal Superior de Justicia, Tribunal de Conciliación y Arbitraje, Tribunal de Disciplina Judicial, u Órgano de Administración Judicial) y a un capítulo de gasto (1000 Servicios Personales, 2000 Materiales y Suministros, 3000 Servicios Generales, 6000 Inversión Pública / Obra), identificándola mediante un número oficial de cartera y una clave programática de 11 segmentos.

2 Objetivo y Alcance

Objetivo: Proporcionar un repositorio centralizado, versionado por ejercicio fiscal, que relacione los órganos y capítulos del PJEV con las especificaciones de cartera, clave programática y nemotécnico de caja exigidas por SEFIPLAN, garantizando que el desglose de ministraciones en 04.2.1 sea ágil, exacto y totalmente auditable ante el ORFIS.

Dentro del Alcance Fuera del Alcance
  • Mapeo por ejercicio fiscal de Órgano (TSJ, TCA, TDJ, OAJ) y Capítulo (1000..6000).
  • Almacenamiento y desglose validado de los 11 segmentos programáticos SEFIPLAN.
  • Asociación de la Cartera SEFIPLAN (ej. 000184001, 000186001, 000618001, 000619001).
  • Nemotécnicos oficiales de Caja (1 OPE-1, 1 NOM-1, 1 OPE-2, 1 OPE-7, 1 OPE-8).
  • Servicio API /resolver para autocompletar renglones de captura en el formulario compuesto de ingresos.
  • Historial y vigencia anual con soft-delete (estatus_registro = 0).
  • Generación de claves programáticas internas del COG del PJEV (pertenecen a Presupuesto 02.1).
  • Afectación presupuestal del gasto del ente (se gestiona en Egresos / CxP 05.2).
  • Alteración de cuentas contables de bancos (administradas en 04.1.4).

6 Procedimientos Almacenados (Stored Procedures)

Gobernanza transaccional en PostgreSQL bajo convención SECURITY DEFINER, SET search_path y respuesta estándar JSONB.

6.1. Procedimiento LEER (ingresos.fn_leer_claves_sefiplan)

CREATE OR REPLACE FUNCTION ingresos.fn_leer_claves_sefiplan(
    p_usuario VARCHAR,
    p_ejercicio SMALLINT DEFAULT 2026,
    p_organo_id VARCHAR DEFAULT NULL,
    p_solo_activos BOOLEAN DEFAULT TRUE
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = ingresos, config, public
AS $$
DECLARE
    v_data JSONB;
BEGIN
    SELECT jsonb_agg(
        jsonb_build_object(
            'clave_sefiplan_id', c.clave_sefiplan_id,
            'ejercicio_fiscal', c.ejercicio_fiscal,
            'organo_id', c.organo_id,
            'organo_desc', c.organo_desc,
            'capitulo_gasto', c.capitulo_gasto,
            'capitulo_desc', c.capitulo_desc,
            'cartera_sefiplan', c.cartera_sefiplan,
            'clave_programatica_11', c.clave_programatica_11,
            'cuenta_caja_nemotecnico', c.cuenta_caja_nemotecnico,
            'tipo_gasto', c.tipo_gasto,
            'es_vigente', c.es_vigente,
            'observaciones', c.observaciones,
            'estatus_registro', c.estatus_registro
        ) ORDER BY c.organo_id, c.capitulo_gasto
    )
    INTO v_data
    FROM ingresos.cat_claves_presupuestales_sefiplan c
    WHERE c.ejercicio_fiscal = p_ejercicio
      AND (p_organo_id IS NULL OR c.organo_id = p_organo_id)
      AND (NOT p_solo_activos OR (c.estatus_registro = 1 AND c.es_vigente = TRUE));

    RETURN jsonb_build_object(
        'error', 0,
        'mensaje', 'Claves SEFIPLAN recuperadas exitosamente.',
        'data', COALESCE(v_data, '[]'::jsonb)
    );
EXCEPTION WHEN OTHERS THEN
    RETURN jsonb_build_object('error', -2, 'mensaje', 'Error al consultar catálogo SEFIPLAN: ' || SQLERRM, 'data', NULL);
END;
$$;

6.2. Procedimiento CRUD (ingresos.fn_crud_claves_sefiplan)

CREATE OR REPLACE FUNCTION ingresos.fn_crud_claves_sefiplan(
    p_accion VARCHAR,
    p_usuario VARCHAR,
    p_payload JSONB
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = ingresos, config, public
AS $$
DECLARE
    v_id BIGINT;
    v_ejercicio SMALLINT;
    v_organo VARCHAR;
    v_capitulo VARCHAR;
    v_clave_11 VARCHAR;
BEGIN
    IF p_accion = 'CREAR' THEN
        v_ejercicio := (p_payload->>'ejercicio_fiscal')::SMALLINT;
        v_organo    := UPPER(TRIM(p_payload->>'organo_id'));
        v_capitulo  := TRIM(p_payload->>'capitulo_gasto');
        v_clave_11  := TRIM(p_payload->>'clave_programatica_11');

        -- Validación de existencia previa
        IF EXISTS (
            SELECT 1 FROM ingresos.cat_claves_presupuestales_sefiplan
            WHERE ejercicio_fiscal = v_ejercicio
              AND organo_id = v_organo
              AND capitulo_gasto = v_capitulo
              AND estatus_registro = 1
        ) THEN
            RETURN jsonb_build_object('error', -1, 'mensaje', 'Ya existe una clave activa para ese Órgano y Capítulo en el ejercicio ' || v_ejercicio);
        END IF;

        -- Validación de 11 segmentos
        IF array_length(string_to_array(v_clave_11, '.'), 1) != 11 THEN
            RETURN jsonb_build_object('error', -1, 'mensaje', 'La clave programática debe contener exactamente 11 segmentos separados por punto.');
        END IF;

        INSERT INTO ingresos.cat_claves_presupuestales_sefiplan (
            ejercicio_fiscal, organo_id, organo_desc, capitulo_gasto, capitulo_desc,
            cartera_sefiplan, clave_programatica_11, cuenta_caja_nemotecnico,
            tipo_gasto, es_vigente, observaciones, estatus_registro, usuario_c, fecha_c
        ) VALUES (
            v_ejercicio, v_organo, TRIM(p_payload->>'organo_desc'),
            v_capitulo, TRIM(p_payload->>'capitulo_desc'),
            TRIM(p_payload->>'cartera_sefiplan'), v_clave_11,
            TRIM(p_payload->>'cuenta_caja_nemotecnico'),
            p_payload->>'tipo_gasto', TRUE,
            p_payload->>'observaciones', 1, p_usuario, CURRENT_TIMESTAMP
        ) RETURNING clave_sefiplan_id INTO v_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Clave SEFIPLAN registrada con éxito.', 'data', jsonb_build_object('clave_sefiplan_id', v_id));

    ELSIF p_accion = 'EDITAR' THEN
        v_id := (p_payload->>'clave_sefiplan_id')::BIGINT;
        v_clave_11 := TRIM(p_payload->>'clave_programatica_11');

        IF array_length(string_to_array(v_clave_11, '.'), 1) != 11 THEN
            RETURN jsonb_build_object('error', -1, 'mensaje', 'La clave programática debe contener exactamente 11 segmentos separados por punto.');
        END IF;

        UPDATE ingresos.cat_claves_presupuestales_sefiplan SET
            cartera_sefiplan        = TRIM(p_payload->>'cartera_sefiplan'),
            clave_programatica_11   = v_clave_11,
            cuenta_caja_nemotecnico = TRIM(p_payload->>'cuenta_caja_nemotecnico'),
            tipo_gasto              = p_payload->>'tipo_gasto',
            observaciones           = p_payload->>'observaciones',
            usuario_m               = p_usuario,
            fecha_m                 = CURRENT_TIMESTAMP
        WHERE clave_sefiplan_id = v_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Clave SEFIPLAN actualizada.', 'data', jsonb_build_object('clave_sefiplan_id', v_id));

    ELSIF p_accion = 'CAMBIAR_ESTATUS' THEN
        v_id := (p_payload->>'clave_sefiplan_id')::BIGINT;
        UPDATE ingresos.cat_claves_presupuestales_sefiplan SET
            estatus_registro = (p_payload->>'estatus_registro')::SMALLINT,
            usuario_m        = p_usuario,
            fecha_m          = CURRENT_TIMESTAMP
        WHERE clave_sefiplan_id = v_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Estatus actualizado.', 'data', jsonb_build_object('clave_sefiplan_id', v_id));
    END IF;

    RETURN jsonb_build_object('error', -1, 'mensaje', 'Acción no soportada: ' || p_accion, 'data', NULL);
END;
$$;

// NestJS Controller: ClavesSefiplanController
@ApiTags('04.1.3 Claves Presupuestales y Carteras SEFIPLAN')
@Controller('api/v1/ingresos/claves-sefiplan')
@UseGuards(JwtAuthGuard, RolesGuard)
export class ClavesSefiplanController {
  constructor(private readonly service: ClavesSefiplanService) {}

  @Get()
  @ApiOperation({ summary: 'Listar claves presupuestales SEFIPLAN por ejercicio y órgano' })
  async listar(
    @Query('ejercicio') ejercicio: number = 2026,
    @Query('organo') organo?: string,
    @CurrentUser() user: UserSession
  ) {
    return this.service.leerClaves(user.username, ejercicio, organo);
  }

  @Get('resolver')
  @ApiOperation({ summary: 'Resolver clave de 11 segmentos, cartera y cuenta de caja para captura en 04.2.1' })
  async resolver(
    @Query('ejercicio') ejercicio: number,
    @Query('organo') organo: string,
    @Query('capitulo') capitulo: string,
    @CurrentUser() user: UserSession
  ) {
    return this.service.resolverClave(user.username, ejercicio, organo, capitulo);
  }

  @Post()
  @ApiOperation({ summary: 'Registrar nueva clave programática SEFIPLAN' })
  async crear(@Body() dto: CreateClaveSefiplanDto, @CurrentUser() user: UserSession) {
    return this.service.crudClave('CREAR', user.username, dto);
  }

  @Put(':id')
  @ApiOperation({ summary: 'Actualizar clave o cartera SEFIPLAN existente' })
  async actualizar(
    @Param('id', ParseIntPipe) id: number,
    @Body() dto: UpdateClaveSefiplanDto,
    @CurrentUser() user: UserSession
  ) {
    return this.service.crudClave('EDITAR', user.username, { ...dto, clave_sefiplan_id: id });
  }

  @Patch(':id/estatus')
  @ApiOperation({ summary: 'Cambiar estatus de vigencia o baja lógica' })
  async cambiarEstatus(
    @Param('id', ParseIntPipe) id: number,
    @Body() dto: CambiarEstatusDto,
    @CurrentUser() user: UserSession
  ) {
    return this.service.crudClave('CAMBIAR_ESTATUS', user.username, { ...dto, clave_sefiplan_id: id });
  }
}
8 Reglas de Negocio Institucionales
CódigoReglaDescripción Operativa
RN-SEF-01 Estructura Rigurosa de 11 Segmentos La clave programática debe respetar invariablemente el formato oficial de 11 segmentos delimitados por puntos: [Capítulo].[Órgano].[Programa].[Subprograma].[Eje].[Financiamiento].[Fuente].[Objeto].[Partida].[Ente].[Cartera]. El SP rechaza cualquier cadena con diferente número de segmentos.
RN-SEF-02 Unicidad por Órgano, Capítulo y Ejercicio No puede existir más de una clave SEFIPLAN activa para la misma combinación de ejercicio_fiscal, organo_id y capitulo_gasto, previniendo ambigüedades en la resolución automática de movimientos.
RN-SEF-03 Correspondencia Forzosa de Cartera El último segmento de la clave programática (Segmento 11) debe coincidir idénticamente con el valor del campo cartera_sefiplan (ej. 000184001 para TSJ).
RN-SEF-04 Desacoplamiento del Formulario 04.2.1 El formulario de registro de ministraciones 04.2.1 tiene estrictamente prohibido permitir la captura manual libre de cadenas programáticas de SEFIPLAN. La asignación se efectúa invocando el servicio /resolver.
RN-SEF-05 Nemotécnico Oficial de Caja Toda clave ligada a gasto operativo ordinario (Capítulos 2000, 3000, 6000) debe registrar su nemotécnico 1 OPE-X, y las asignadas a nómina o servicios personales (Capítulo 1000) deben asignarse a 1 NOM-X, garantizando el cuadre con las fichas de caja del Estado.
RN-SEF-06 Inmutabilidad con Registros Relacionados Si una clave programática ya fue utilizada en partidas de ingresos autorizadas o conciliadas en 04.2.1, el sistema bloquea su edición de ejercicio o estructura; únicamente se permite su inactivación lógica (es_vigente = false).
