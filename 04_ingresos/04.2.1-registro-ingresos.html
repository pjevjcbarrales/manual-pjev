04.2.1

Registro de ingresos

Captura de ministraciones, distribución por organización y capítulo, consulta e impresión de la solicitud.

Etapa 2 · Caja Modal compuesto Responsable de desarrollo · Daryl Revisión 3.1.1 · 13 de noviembre de 2026

1 Descripción general

Caja registra solicitudes de ministración, completa su distribución por organización y capítulo y consulta o imprime el reporte de la captura guardada. Un registro parcial se conserva como borrador. El servidor clasifica como solicitado el registro completo cuyo detalle cuadra con el encabezado.

La pantalla instalada es /caja/registro-ingresos. El alcance verificado incluye clasificación para la captura, alta, edición, consulta e impresión. La confirmación bancaria, el devengo, la recaudación y la generación de pólizas pertenecen a otros flujos.

4 Modelo de datos

Las tablas muestran los nombres finales del diseño. La llave va primero, seguida por los datos en orden de registro y por estado y auditoría al final. Las columnas de negocio llevan rm_ en Encabezado y rmm_ en Movimientos, incluidas sus referencias. Se conservan los nombres comunes de vigencia y auditoría conforme al estándar PostgreSQL del SIAF.

Los nombres finales requieren migración. Los tipos, la nulabilidad, los valores predeterminados y las relaciones corresponden al esquema cotejado en PostgreSQL local. El contrato de la pantalla y el SQL desplegado se describen en Funciones PostgreSQL y Servicios REST.

El encabezado tiene PK (rm_id) e índice de consulta de activos por (rm_ejercicio, rm_fecha_operacion, rm_id). El movimiento tiene PK (rmm_id), FK al encabezado y unicidad en (rmm_ministracion_id, rmm_numero_linea). El ejercicio del movimiento se obtiene del encabezado. La fecha de operación, la fecha de oficio y el mes de ministración representan datos distintos.

Se conservan la revisión y las claves y huellas de alta y edición porque controlan la concurrencia y los reintentos. El nombre del autor permite reproducir quién elaboró el reporte. El concepto automático, el total del detalle y la diferencia se calculan, y el nombre de organización se consulta en su catálogo. La base local carecía de capturas de ministración al verificar, por lo que la revisión de necesidad se apoya en los consumidores del código.

Identificadores del contrato instalado

El encabezado usa operacion_id, ejercicio_fiscal y estatus_codigo. El movimiento usa movimiento_id y operacion_id como referencia al encabezado. El índice de activos usa (ejercicio_fiscal, fecha_operacion, operacion_id). El catálogo de estados utiliza la llave codigo char(2) y nombre varchar(30).

Definición SQL instalada de fn_leer_subtipos_tramite 
CREATE OR REPLACE FUNCTION ingresos.fn_leer_subtipos_tramite(p_usuario character varying, p_solo_activos boolean DEFAULT true, p_tipo_principal character varying DEFAULT NULL::character varying, p_buscar character varying DEFAULT NULL::character varying, p_subtipo_id bigint DEFAULT NULL::bigint)
     RETURNS jsonb
     LANGUAGE plpgsql
     STABLE SECURITY DEFINER
     SET search_path TO 'pg_catalog', 'ingresos', 'config', 'contabilidad'
    AS $function$
    DECLARE
      v_data JSONB;
    BEGIN
      IF p_usuario IS NULL OR btrim(p_usuario) = '' THEN
        RETURN jsonb_build_object('cod_resultado', -1, 'msg_resultado', 'Se requiere un usuario válido.', 'data', NULL);
      END IF;
      IF p_tipo_principal IS NOT NULL AND upper(btrim(p_tipo_principal)) NOT IN
        ('MINISTRACIONES', 'PROPIOS', 'REINTEGROS', 'NO_PRESUPUESTARIO') THEN
        RETURN jsonb_build_object('cod_resultado', -1, 'msg_resultado', 'La familia solicitada no es válida.', 'data', NULL);
      END IF;

      SELECT COALESCE(jsonb_agg(to_jsonb(fila) ORDER BY fila.tipo_principal, fila.subtipo_tramite_id), '[]'::jsonb)
      INTO v_data
      FROM (
        SELECT
          st.subtipo_tramite_id, st.tipo_principal, st.clave_subtipo,
          st.nombre_subtipo, st.descripcion_card, st.icono_svg,
          st.tipo_contraparte, st.afecta_presupuesto, st.momento_inicial,
          st.permite_devengado_previo, st.requiere_oficio, st.requiere_capitulo,
          st.requiere_cuenta_bancaria, st.cri_id_default,
          cri.cri_cuentacompleta AS cri_clave_default,
          cri.cri_descripcion AS cri_descripcion_default,
          st.fuente_id_default, cff.cff_clave AS fuente_clave_default,
          cff.cff_nombre AS fuente_nombre_default,
          st.mcr_matriz_id, mcv.mcv_clave AS matriz_clave,
          mcv.mcv_nombre AS matriz_nombre, mcv.mcv_estado AS matriz_estado,
          st.estatus_registro, st.usuario_c, st.fecha_c, st.usuario_m, st.fecha_m
        FROM ingresos.cat_subtipos_tramite_ingreso st
        LEFT JOIN config.catalogo_cri cri ON cri.cri_id = st.cri_id_default
        LEFT JOIN config.catalogo_fuentes_fin cff ON cff.cff_id = st.fuente_id_default
        LEFT JOIN contabilidad.matriz_conversion mcv ON mcv.mcv_id = st.mcr_matriz_id
        WHERE (NOT p_solo_activos OR st.estatus_registro = 1)
          AND (p_tipo_principal IS NULL OR st.tipo_principal = upper(btrim(p_tipo_principal)))
          AND (p_subtipo_id IS NULL OR st.subtipo_tramite_id = p_subtipo_id)
          AND (p_buscar IS NULL OR btrim(p_buscar) = ''
            OR st.clave_subtipo ILIKE '%' || btrim(p_buscar) || '%'
            OR st.nombre_subtipo ILIKE '%' || btrim(p_buscar) || '%'
            OR st.descripcion_card ILIKE '%' || btrim(p_buscar) || '%')
      ) fila;

      IF p_subtipo_id IS NOT NULL AND jsonb_array_length(v_data) = 0 THEN
        RETURN jsonb_build_object('cod_resultado', -1, 'msg_resultado', 'El subtipo solicitado no existe.', 'data', NULL);
      END IF;
      RETURN jsonb_build_object(
        'cod_resultado', 0,
        'msg_resultado', 'Subtipos de trámite recuperados exitosamente.',
        'data', CASE WHEN p_subtipo_id IS NULL THEN v_data ELSE v_data->0 END
      );
    EXCEPTION WHEN OTHERS THEN
      RETURN jsonb_build_object('cod_resultado', -2, 'msg_resultado', 'No fue posible consultar los subtipos de trámite.', 'data', NULL);
    END;
    $function$

     RETURNS TABLE(grupo_id bigint, grupo_codigo text, grupo_nombre text, procedimiento_id bigint, procedimiento_codigo text, procedimiento_nombre text)
     LANGUAGE sql
     STABLE
     SET search_path TO 'pg_catalog'
    AS $function$
        SELECT grupo.matriz_grupo_id,
               grupo.mgt_codigo::text,
               grupo.mgt_titulo::text,
               procedimiento.matriz_grupo_procedimiento_id,

Definición SQL instalada de fn_bloquear_movimiento_ministracion 
CREATE OR REPLACE FUNCTION ingresos.fn_bloquear_movimiento_ministracion()
     RETURNS trigger
     LANGUAGE plpgsql
     SET search_path TO 'pg_catalog', 'ingresos'
    AS $function$
    DECLARE v_operacion BIGINT;
    BEGIN
      IF TG_OP='UPDATE' AND NEW.operacion_id <> OLD.operacion_id THEN
        RAISE EXCEPTION 'Un movimiento no puede trasladarse a otra operación.' USING ERRCODE='23514';
      END IF;
      v_operacion := CASE WHEN TG_OP='DELETE' THEN OLD.operacion_id ELSE NEW.operacion_id END;
      PERFORM 1 FROM ingresos.registro_ministracion WHERE operacion_id=v_operacion FOR UPDATE;
      IF TG_OP='DELETE' THEN RETURN OLD; END IF;
      RETURN NEW;
    END;
    $function$
Definición SQL instalada de fn_validar_captura_ministracion 
CREATE OR REPLACE FUNCTION ingresos.fn_validar_captura_ministracion()
     RETURNS trigger
     LANGUAGE plpgsql
     SET search_path TO 'pg_catalog', 'ingresos', 'config'
    AS $function$
    DECLARE v_operacion BIGINT; v_enc ingresos.registro_ministracion%ROWTYPE; v_suma NUMERIC;
    BEGIN
      v_operacion := CASE WHEN TG_OP='DELETE' THEN OLD.operacion_id ELSE NEW.operacion_id END;
      SELECT * INTO v_enc FROM ingresos.registro_ministracion WHERE operacion_id=v_operacion FOR UPDATE;
      IF NOT FOUND OR v_enc.estatus_registro=0 THEN RETURN NULL; END IF;
      IF v_enc.cuenta_bancaria_id IS NOT NULL AND NOT EXISTS (
        SELECT 1 FROM config.cat_cuentas_bancarias
        WHERE cuenta_bancaria_id=v_enc.cuenta_bancaria_id AND estatus_registro=1
      ) THEN
        RAISE EXCEPTION 'La cuenta bancaria institucional no está activa.' USING ERRCODE='23514';
      END IF;
      SELECT coalesce(sum(importe),0) INTO v_suma FROM ingresos.registro_ministracion_movimiento
        WHERE operacion_id=v_operacion AND estatus_registro=1;
      IF (v_enc.importe_total IS NULL AND v_suma>0) OR v_suma>v_enc.importe_total THEN
        RAISE EXCEPTION 'La suma de movimientos supera el importe del encabezado.' USING ERRCODE='23514';
      END IF;
      IF EXISTS (
        SELECT 1 FROM ingresos.registro_ministracion_movimiento m
        WHERE m.operacion_id=v_operacion AND m.estatus_registro=1 AND m.capitulo IS NOT NULL
        AND (v_enc.tipo_ministracion IS NULL
          OR (v_enc.tipo_ministracion='NOMINA' AND m.capitulo<>1000)
          OR (v_enc.tipo_ministracion='OPERACION' AND m.capitulo NOT IN (2000,3000,5000,6000)))
      ) THEN
        RAISE EXCEPTION 'El capítulo no corresponde al tipo de ministración.' USING ERRCODE='23514';
      END IF;
      IF EXISTS (
        SELECT 1 FROM ingresos.registro_ministracion_movimiento m
        JOIN config.catalogo_centros_costos cc ON cc.cc_id=m.organizacion_id
        WHERE m.operacion_id=v_operacion AND m.estatus_registro=1 AND
          (cc.estatus_registro<>1 OR coalesce(cc.cc_clave_pptal,cc.cc_clave) NOT IN ('301C11001','301C21001','301C71001','301C81001')
           OR coalesce(cc.cc_vigencia_inicio, DATE '1900-01-01')>make_date(v_enc.ejercicio_fiscal,12,31)
           OR coalesce(cc.cc_vigencia_fin, DATE '2099-12-31')<make_date(v_enc.ejercicio_fiscal,1,1))
      ) THEN
        RAISE EXCEPTION 'La organización no está disponible para esta captura y ejercicio.' USING ERRCODE='23514';
      END IF;
      RETURN NULL;
    END;
    $function$

En el esquema instalado, la unicidad de alta es (usuario_c, idempotencia_clave). La edición conserva la última clave y huella de actualización. Reintentar esa edición exige el mismo actor y contenido. La API devuelve cod_resultado = 0, msg_resultado y data en operaciones exitosas. Devuelve errores HTTP para datos inválidos (400), permiso insuficiente (403), registro inexistente (404), conflicto (409) o indisponibilidad (503).

10 Flujos de integración

MóduloIntercambio
Cuentas bancarias institucionales y Centros de costosLa captura consulta cuentas activas y organizaciones del ejercicio.
Configuración Inicial · FirmasEl reporte consulta /api/configuracion/firmas/documentos y /api/configuracion/firmas/vigentes para SOLCOM-R.
Matriz de ConversiónLa ruta de clasificación de matriz consulta los procedimientos de ingresos. El asistente de la pantalla usa el endpoint de subtipos para captura.
Depósitos, devengo y recaudaciónEl controlador de captura carece de operaciones de vincular, aplicar o cancelar depósitos. El controlador separado /api/v1/caja/registro expone otras operaciones, ajenas al flujo de esta pantalla.

Trazabilidad y minería de procesos

La captura conserva operación, ejercicio, periodo, estado, revisión, usuario y fechas de creación y modificación. La función genérica de eventos propuesta podría registrar el guardado exitoso dentro de la misma transacción Prisma y la emisión del reporte desde el servicio cuando se defina como actividad formal. Correlacionar por operación, ejercicio y revisión. Registrar actor, fecha real, actividad, estado anterior y nuevo cuando cambie, y resultado. Los reintentos idempotentes deben conservar un solo evento de negocio.

El diseño previo del expediente preveía conservar el oficio DGA a SEFIPLAN con acuse y la solicitud firmada. La API de captura vigente carece de campos para adjuntar esos documentos. El reporte consultado desde el módulo contiene los datos y nombres de firma, y la conservación de los documentos firmados corresponde al expediente institucional.
