04.1.4

Cuentas Bancarias Recaudadoras

Catálogo maestro del padrón de cuentas bancarias institucionales del Poder Judicial donde radican los depósitos de ministraciones estatales, aranceles, fondos auxiliares y consignaciones, enlazadas unívocamente al Plan de Cuentas (COA 1.1.1.2).

Modo B — Catálogo Institucional de Tesorería Tipo: Análisis Funcional (DOC-08) Responsable: Daryl
📌 Vínculo Bancario Institucional y Enlace Contable Inmutable

A diferencia de los conceptos de ingreso (que clasifican el por qué se percibe un recurso), este catálogo administra el dónde ingresa materialmente el flujo de efectivo. Cada cuenta bancaria registrada debe contar forzosamente con una subcuenta contable de la clase 1.1.1.2 Bancos / Tesorería en el Catálogo de Cuentas (COA).

Principio de Conciliación: La existencia de este catálogo alimenta el selector de cuenta en el encabezado de 04.2.1 y permite el cotejo automático de depósitos en el módulo 04.3.1 Conciliación de Ingresos, evitando inconsistencias entre los estados de cuenta bancarios y la contabilidad gubernamental.

1 Descripción General

El catálogo 04.1.4 Cuentas Bancarias Recaudadoras constituye el registro formal de las cuentas de cheques e inversión aperturadas a nombre del Poder Judicial del Estado de Veracruz en las instituciones financieras autorizadas (BBVA México, Banorte, Santander, etc.).

Su función primordial es regular la radicación del efectivo que ingresa al Tribunal, ya sea por ministraciones presupuestales ordinarias o extraordinarias remitidas por SEFIPLAN, recaudación de aranceles judiciales, pagos de peritajes y derechos de copias en el Fondo Auxiliar para la Impartición de Justicia, o consignaciones en juzgados de primera instancia.

2 Objetivo y Alcance

Objetivo: Garantizar el control estricto, la parametrización bancaria y la vinculación contable obligatoria de las cuentas recaudadoras institucionales del PJEV, proveyendo al subsistema de ingresos de datos bancarios verificados (CLABE de 18 dígitos con algoritmo de chequeo, convenios CIE y subcuenta contable específica).

Dentro del Alcance Fuera del Alcance
  • Padrón institucional de cuentas bancarias activas del PJEV.
  • Validación sintáctica y de longitud de la CLABE Interbancaria (18 dígitos).
  • Registro de convenios de cobranza (CIE BBVA u homólogos) para ventanilla y practicajas.
  • Tipificación del fondo institucional (Ministración, Fondo Auxiliar, Recursos Propios, Juzgados).
  • Asignación forzosa de la subcuenta de activo 1.1.1.2.X del Plan de Cuentas.
  • Inmutabilidad y protección contra borrado físico si la cuenta posee movimientos registrados.
  • Emisión y dispersión de cheques o transferencias de pago a proveedores o nómina (corresponde a Egresos / Pagos 06.2).
  • Cálculo de conciliación bancaria mensual (se realiza en 03.3.2 y 04.3.1).
  • Apertura o cancelación jurídica de contratos con las entidades bancarias (proceso extra-sistema).

6 Procedimientos Almacenados (Stored Procedures)

Gobernanza transaccional en PostgreSQL bajo convención SECURITY DEFINER, SET search_path y respuesta estándar JSONB.

6.1. Procedimiento LEER (ingresos.fn_leer_cuentas_recaudadoras)

CREATE OR REPLACE FUNCTION ingresos.fn_leer_cuentas_recaudadoras(
    p_usuario VARCHAR,
    p_tipo_fondo VARCHAR DEFAULT NULL,
    p_solo_activos BOOLEAN DEFAULT TRUE
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = ingresos, contabilidad, config, public
AS $$
DECLARE
    v_data JSONB;
BEGIN
    SELECT jsonb_agg(
        jsonb_build_object(
            'cuenta_recaudadora_id', cr.cuenta_recaudadora_id,
            'institucion_bancaria', cr.institucion_bancaria,
            'numero_cuenta', cr.numero_cuenta,
            'clabe_interbancaria', cr.clabe_interbancaria,
            'sucursal', cr.sucursal,
            'convenio_cie', cr.convenio_cie,
            'nombre_identificador', cr.nombre_identificador,
            'tipo_fondo', cr.tipo_fondo,
            'cuenta_contable_id', cr.cuenta_contable_id,
            'cuenta_contable_clave', cc.clave,
            'cuenta_contable_desc', cc.nombre,
            'saldo_inicial', cr.saldo_inicial,
            'permite_deposito_directo', cr.permite_deposito_directo,
            'estatus_registro', cr.estatus_registro
        ) ORDER BY cr.cuenta_recaudadora_id
    )
    INTO v_data
    FROM ingresos.cat_cuentas_recaudadoras cr
    LEFT JOIN contabilidad.cat_cuentas cc ON cc.cuenta_id = cr.cuenta_contable_id
    WHERE (NOT p_solo_activos OR cr.estatus_registro = 1)
      AND (p_tipo_fondo IS NULL OR cr.tipo_fondo = p_tipo_fondo);

    RETURN jsonb_build_object(
        'error', 0,
        'mensaje', 'Cuentas recaudadoras recuperadas exitosamente.',
        'data', COALESCE(v_data, '[]'::jsonb)
    );
EXCEPTION WHEN OTHERS THEN
    RETURN jsonb_build_object('error', -2, 'mensaje', 'Error al consultar cuentas recaudadoras: ' || SQLERRM, 'data', NULL);
END;
$$;

6.2. Procedimiento CRUD (ingresos.fn_crud_cuentas_recaudadoras)

CREATE OR REPLACE FUNCTION ingresos.fn_crud_cuentas_recaudadoras(
    p_accion VARCHAR,
    p_usuario VARCHAR,
    p_payload JSONB
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = ingresos, contabilidad, config, public
AS $$
DECLARE
    v_id BIGINT;
    v_clabe VARCHAR;
    v_cuenta VARCHAR;
    v_banco VARCHAR;
    v_cta_contable_id BIGINT;
BEGIN
    IF p_accion = 'CREAR' THEN
        v_banco           := TRIM(p_payload->>'institucion_bancaria');
        v_cuenta          := TRIM(p_payload->>'numero_cuenta');
        v_clabe           := TRIM(p_payload->>'clabe_interbancaria');
        v_cta_contable_id := (p_payload->>'cuenta_contable_id')::BIGINT;

        -- Validación de 18 dígitos en CLABE
        IF length(v_clabe) != 18 OR v_clabe !~ '^[0-9]+$' THEN
            RETURN jsonb_build_object('error', -1, 'mensaje', 'La CLABE interbancaria debe tener exactamente 18 dígitos numéricos.');
        END IF;

        -- Unicidad de cuenta bancaria en el mismo banco
        IF EXISTS (
            SELECT 1 FROM ingresos.cat_cuentas_recaudadoras
            WHERE institucion_bancaria = v_banco
              AND numero_cuenta = v_cuenta
              AND estatus_registro = 1
        ) THEN
            RETURN jsonb_build_object('error', -1, 'mensaje', 'Ya existe una cuenta activa con ese número para ' || v_banco);
        END IF;

        -- Validación de existencia de cuenta contable 1.1.1.2
        IF NOT EXISTS (
            SELECT 1 FROM contabilidad.cat_cuentas
            WHERE cuenta_id = v_cta_contable_id
              AND clave LIKE '1.1.1.2%'
        ) THEN
            RETURN jsonb_build_object('error', -1, 'mensaje', 'La cuenta contable debe pertenecer a la clase 1.1.1.2 (Bancos / Tesorería).');
        END IF;

        INSERT INTO ingresos.cat_cuentas_recaudadoras (
            institucion_bancaria, numero_cuenta, clabe_interbancaria, sucursal,
            convenio_cie, nombre_identificador, tipo_fondo, cuenta_contable_id,
            saldo_inicial, permite_deposito_directo, estatus_registro,
            usuario_c, fecha_c
        ) VALUES (
            v_banco, v_cuenta, v_clabe, TRIM(p_payload->>'sucursal'),
            TRIM(p_payload->>'convenio_cie'), TRIM(p_payload->>'nombre_identificador'),
            p_payload->>'tipo_fondo', v_cta_contable_id,
            COALESCE((p_payload->>'saldo_inicial')::NUMERIC, 0.00),
            COALESCE((p_payload->>'permite_deposito_directo')::BOOLEAN, TRUE),
            1, p_usuario, CURRENT_TIMESTAMP
        ) RETURNING cuenta_recaudadora_id INTO v_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Cuenta recaudadora registrada exitosamente.', 'data', jsonb_build_object('cuenta_recaudadora_id', v_id));

    ELSIF p_accion = 'EDITAR' THEN
        v_id := (p_payload->>'cuenta_recaudadora_id')::BIGINT;
        v_clabe := TRIM(p_payload->>'clabe_interbancaria');

        IF length(v_clabe) != 18 OR v_clabe !~ '^[0-9]+$' THEN
            RETURN jsonb_build_object('error', -1, 'mensaje', 'La CLABE interbancaria debe tener exactamente 18 dígitos numéricos.');
        END IF;

        UPDATE ingresos.cat_cuentas_recaudadoras SET
            sucursal                 = TRIM(p_payload->>'sucursal'),
            convenio_cie             = TRIM(p_payload->>'convenio_cie'),
            nombre_identificador     = TRIM(p_payload->>'nombre_identificador'),
            permite_deposito_directo = (p_payload->>'permite_deposito_directo')::BOOLEAN,
            usuario_m                = p_usuario,
            fecha_m                  = CURRENT_TIMESTAMP
        WHERE cuenta_recaudadora_id = v_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Cuenta recaudadora actualizada.', 'data', jsonb_build_object('cuenta_recaudadora_id', v_id));

    ELSIF p_accion = 'CAMBIAR_ESTATUS' THEN
        v_id := (p_payload->>'cuenta_recaudadora_id')::BIGINT;

        -- Protección: No inactivar si existen ingresos con saldo o en tránsito
        IF (p_payload->>'estatus_registro')::SMALLINT = 0 THEN
            IF EXISTS (
                SELECT 1 FROM ingresos.ing_ingresos
                WHERE cuenta_bancaria_id = v_id
                  AND estado_ingreso NOT IN ('CANCELADO')
            ) THEN
                RETURN jsonb_build_object('error', -1, 'mensaje', 'No se puede inactivar una cuenta con ingresos registrados vigentes.');
            END IF;
        END IF;

        UPDATE ingresos.cat_cuentas_recaudadoras SET
            estatus_registro = (p_payload->>'estatus_registro')::SMALLINT,
            usuario_m        = p_usuario,
            fecha_m          = CURRENT_TIMESTAMP
        WHERE cuenta_recaudadora_id = v_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Estatus de la cuenta actualizado.', 'data', jsonb_build_object('cuenta_recaudadora_id', v_id));
    END IF;

    RETURN jsonb_build_object('error', -1, 'mensaje', 'Acción no soportada: ' || p_accion, 'data', NULL);
END;
$$;

POST /api/v1/ingresos/cuentas-recaudadoras Body: CreateCuentaRecaudadoraDto Registrar una nueva cuenta bancaria con validación de 18 dígitos CLABE.

// NestJS Controller: CuentasRecaudadorasController
@ApiTags('04.1.4 Cuentas Bancarias Recaudadoras')
@Controller('api/v1/ingresos/cuentas-recaudadoras')
@UseGuards(JwtAuthGuard, RolesGuard)
export class CuentasRecaudadorasController {
  constructor(private readonly service: CuentasRecaudadorasService) {}

  @Get()
  @ApiOperation({ summary: 'Listar cuentas bancarias recaudadoras activas' })
  async listar(
    @Query('tipo_fondo') tipoFondo?: string,
    @CurrentUser() user: UserSession
  ) {
    return this.service.leerCuentas(user.username, tipoFondo);
  }

  @Post()
  @ApiOperation({ summary: 'Registrar nueva cuenta bancaria recaudadora' })
  async crear(@Body() dto: CreateCuentaRecaudadoraDto, @CurrentUser() user: UserSession) {
    return this.service.crudCuenta('CREAR', user.username, dto);
  }

  @Put(':id')
  @ApiOperation({ summary: 'Actualizar datos de una cuenta recaudadora' })
  async actualizar(
    @Param('id', ParseIntPipe) id: number,
    @Body() dto: UpdateCuentaRecaudadoraDto,
    @CurrentUser() user: UserSession
  ) {
    return this.service.crudCuenta('EDITAR', user.username, { ...dto, cuenta_recaudadora_id: id });
  }

  @Patch(':id/estatus')
  @ApiOperation({ summary: 'Modificar estatus de la cuenta bancaria (Baja lógica)' })
  async cambiarEstatus(
    @Param('id', ParseIntPipe) id: number,
    @Body() dto: CambiarEstatusDto,
    @CurrentUser() user: UserSession
  ) {
    return this.service.crudCuenta('CAMBIAR_ESTATUS', user.username, { ...dto, cuenta_recaudadora_id: id });
  }
}
8 Reglas de Negocio Institucionales
CódigoReglaDescripción Operativa
RN-CTA-01 Validación Estricta de 18 Dígitos en CLABE Toda cuenta bancaria debe registrar una CLABE Interbancaria con una longitud exacta de 18 dígitos exclusivamente numéricos. El SP rechaza cualquier registro con longitud diferente.
RN-CTA-02 Unicidad por Institución Bancaria y Cuenta No se permite el registro duplicado de un mismo número de cuenta para una misma entidad financiera mientras el registro previo continúe en estado activo (estatus_registro = 1).
RN-CTA-03 Enlace Contable Forzoso al COA (Clase 1.1.1.2) El campo cuenta_contable_id es obligatorio y debe apuntar ineludiblemente a una subcuenta activa de la clase 1.1.1.2 Bancos / Tesorería. El sistema no permite cuentas de orden ni de resultados.
RN-CTA-04 Inmutabilidad Bancaria de Operaciones Vigentes Una vez que una cuenta bancaria ha registrado depósitos aplicados en el módulo 04.2.1 o participado en conciliaciones de 04.3.1, sus campos estructurales (Banco, Número de Cuenta y Cuenta Contable) quedan bloqueados para edición.
RN-CTA-05 Protección Referencial de Inactivación El SP rechaza la inactivación (baja lógica) de una cuenta recaudadora si existen registros de ingresos en estado RECIBIDO, EN_CONCILIACION o CONCILIADO en el ejercicio en curso.
RN-CTA-06 Filtro Automático en Formularios de Ingresos El selector desplegable "Cuenta Bancaria Destino" del módulo 04.2.1 debe listar únicamente las cuentas activas que tengan habilitada la bandera permite_deposito_directo = true.
