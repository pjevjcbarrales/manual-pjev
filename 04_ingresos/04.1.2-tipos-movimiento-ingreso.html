04.1.2

Pre-pólizas y Reglas de Conversión de Ingresos

Motor determinista de integración contable que traduce los subtipos de trámite de ingreso a sus asientos patrimoniales y presupuestarios oficiales CONAC. Fundamenta el cálculo y despliegue en tiempo real de la Pre-póliza desde el estado Borrador.

Pendiente de desarrollo Análisis funcional canónico (DOC-08) Responsable: Eunice Conexión Directa Matriz 03.1.2
📌 Regla de Oro: Evaluación de la Matriz Oficial desde Modo Borrador

1. Cero Registros Contablemente Ciegos: Cuando el analista captura un trámite en 04.2.1, incluso antes de autorizar o guardar definitivamente (en estado BORRADOR), el sistema consulta las tablas activas de contabilidad.matriz_conversion (Matrices B.1, B.2, B.3) y proyecta de inmediato la Pre-póliza Contable y Presupuestaria.

2. Validación Preventiva Temprana: Si un concepto o partida carece de par contable en la matriz oficial de Contabilidad (03.1.2), el sistema alerta al capturista en el borrador, impidiendo que lleguen operaciones descuadradas al cierre mensual.

3. Ninguna Captura Libre de Cuentas: El usuario de Tesorería no digita cuentas contables. Las cuentas se derivan en estricto apego al Clasificador por Rubro de Ingreso (CRI 01.2.7) y a la Matriz Oficial parametrizada por la Jefatura de Contabilidad.

1 Descripción General

El módulo 04.1.2 Pre-pólizas y Reglas de Conversión de Ingresos es el puente tecnológico entre la operación administrativa de Recursos Financieros (Tesorería) y el Libro Diario de Contabilidad Gubernamental. Sustituye la antigua concepción estática de "tipos de movimiento" por un motor inteligente de conversión automática.

Su función es garantizar el cumplimiento del principio de Registro Único establecido por la Ley General de Contabilidad Gubernamental: toda operación registrada administrativamente (un oficio de ministración, un reintegro de comisiones o un interés bancario) debe producir concurrentemente sus afectaciones patrimoniales y presupuestales sin intervención manual.

3 Mecánica de Evaluación y Persistencia en Modo Borrador

Para asegurar que tanto el capturista como el revisor conozcan el impacto de la transacción antes de autorizarla, el sistema ejecuta el siguiente pipeline determinista:

[1. Captura en Formulario] Usuario elige Subtrámite (04.1.1), teclea importe y líneas de distribución.
  ↓ (Disparo Asíncrono en Frontend o al Guardar Borrador)
[2. Consulta a Matriz Oficial] Llama a ingresos.fn_calcular_prepoliza_ingreso() con p_es_borrador = true.
  ↓ (Evaluación de contabilidad.matriz_conversion matrices 14, 15, 16 o reglas de pasivo)
[3. Armado de Pre-póliza] Asigna Cuentas Contables y Presupuestarias + valida balance aritmético (Debe = Haber).
  ↓
[4. Renderizado UI en Vivo] Despliega bloque interactivo "Pre-póliza Proyectada" con semáforo verde de cuadre.
  ↓
[5. Persistencia de Borrador] Se guarda el encabezado en estatus = 'BORRADOR' y las líneas de pre-póliza asociadas.
  ↓
[6. Formalización Definitiva] Al autorizar o conciliar depósito, la pre-póliza transita intacta al Libro Diario oficial (03.4.1.2).

5 Procedimientos Almacenados (Stored Procedures)

Gobernanza transaccional en PostgreSQL bajo convención SECURITY DEFINER, SET search_path y respuesta estándar JSONB.

5.1. Procedimiento de Cálculo en Tiempo Real (ingresos.fn_calcular_prepoliza_ingreso)

CREATE OR REPLACE FUNCTION ingresos.fn_calcular_prepoliza_ingreso(
    p_usuario VARCHAR,
    p_subtipo_tramite_id BIGINT,
    p_importe DECIMAL(18,2),
    p_distribucion JSONB DEFAULT '[]'::jsonb,
    p_cuenta_bancaria_id BIGINT DEFAULT NULL,
    p_es_borrador BOOLEAN DEFAULT TRUE
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = ingresos, contabilidad, config, public
AS $$
DECLARE
    v_subtipo RECORD;
    v_asientos JSONB := '[]'::jsonb;
    v_suma_debe DECIMAL(18,2) := 0;
    v_suma_haber DECIMAL(18,2) := 0;
    v_cta_bancos RECORD;
    v_cta_deudor RECORD;
    v_cta_ingreso RECORD;
    v_cta_presup_d RECORD;
    v_cta_presup_h RECORD;
BEGIN
    -- 1. Validar importe
    IF p_importe IS NULL OR p_importe <= 0 THEN
        RETURN jsonb_build_object('error', -1, 'mensaje', 'El importe para evaluar la pre-póliza debe ser mayor a cero.', 'data', NULL);
    END IF;

    -- 2. Obtener subtipo de trámite
    SELECT * INTO v_subtipo 
    FROM ingresos.cat_subtipos_tramite_ingreso 
    WHERE subtipo_tramite_id = p_subtipo_tramite_id AND estatus_registro = 1;

    IF NOT FOUND THEN
        RETURN jsonb_build_object('error', -1, 'mensaje', 'Subtipo de trámite de ingreso no encontrado o inactivo.', 'data', NULL);
    END IF;

    -- 3. Generación según Matriz Oficial
    IF v_subtipo.tipo_principal = 'NO_PRESUPUESTARIO' THEN
        -- Depósito No Identificado (Pasivo de custodia 2.1.9.9)
        SELECT cc_id, cc_cuentapuntos, cc_nombre INTO v_cta_bancos 
        FROM contabilidad.catalogo_cuentas WHERE cc_cuentapuntos LIKE '1.1.1.2%' AND estatus_registro = 1 LIMIT 1;

        SELECT cc_id, cc_cuentapuntos, cc_nombre INTO v_cta_deudor 
        FROM contabilidad.catalogo_cuentas WHERE cc_cuentapuntos LIKE '2.1.9.9%' AND estatus_registro = 1 LIMIT 1;

        v_asientos := jsonb_build_array(
            jsonb_build_object('renglon', 1, 'ambito', 'C', 'naturaleza', 'D', 'cuenta_puntos', v_cta_bancos.cc_cuentapuntos, 'cuenta_nombre', v_cta_bancos.cc_nombre, 'cargo', p_importe, 'abono', 0),
            jsonb_build_object('renglon', 2, 'ambito', 'C', 'naturaleza', 'H', 'cuenta_puntos', v_cta_deudor.cc_cuentapuntos, 'cuenta_nombre', v_cta_deudor.cc_nombre, 'cargo', 0, 'abono', p_importe)
        );
        v_suma_debe := p_importe;
        v_suma_haber := p_importe;

    ELSIF v_subtipo.momento_inicial = 'DEVENGADO_PREVIO' THEN
        -- Matriz 14: B.1 Ingreso Devengado (1.1.2.2 vs 4.1.5 y 8.1.2 vs 8.1.4)
        SELECT cc_id, cc_cuentapuntos, cc_nombre INTO v_cta_deudor 
        FROM contabilidad.catalogo_cuentas WHERE cc_cuentapuntos LIKE '1.1.2.2%' AND estatus_registro = 1 LIMIT 1;

        SELECT cc_id, cc_cuentapuntos, cc_nombre INTO v_cta_ingreso 
        FROM contabilidad.catalogo_cuentas WHERE cc_cuentapuntos LIKE '4.1.5%' AND estatus_registro = 1 LIMIT 1;

        SELECT cc_id, cc_cuentapuntos, cc_nombre INTO v_cta_presup_d 
        FROM contabilidad.catalogo_cuentas WHERE cc_cuentapuntos LIKE '8.1.2%' AND estatus_registro = 1 LIMIT 1;

        SELECT cc_id, cc_cuentapuntos, cc_nombre INTO v_cta_presup_h 
        FROM contabilidad.catalogo_cuentas WHERE cc_cuentapuntos LIKE '8.1.4%' AND estatus_registro = 1 LIMIT 1;

        v_asientos := jsonb_build_array(
            jsonb_build_object('renglon', 1, 'ambito', 'C', 'naturaleza', 'D', 'cuenta_puntos', v_cta_deudor.cc_cuentapuntos, 'cuenta_nombre', v_cta_deudor.cc_nombre, 'cargo', p_importe, 'abono', 0),
            jsonb_build_object('renglon', 2, 'ambito', 'C', 'naturaleza', 'H', 'cuenta_puntos', v_cta_ingreso.cc_cuentapuntos, 'cuenta_nombre', v_cta_ingreso.cc_nombre, 'cargo', 0, 'abono', p_importe),
            jsonb_build_object('renglon', 3, 'ambito', 'P', 'naturaleza', 'D', 'cuenta_puntos', v_cta_presup_d.cc_cuentapuntos, 'cuenta_nombre', v_cta_presup_d.cc_nombre, 'cargo', p_importe, 'abono', 0),
            jsonb_build_object('renglon', 4, 'ambito', 'P', 'naturaleza', 'H', 'cuenta_puntos', v_cta_presup_h.cc_cuentapuntos, 'cuenta_nombre', v_cta_presup_h.cc_nombre, 'cargo', 0, 'abono', p_importe)
        );
        v_suma_debe := p_importe * 2;
        v_suma_haber := p_importe * 2;

    ELSE
        -- Matriz 16: B.3 Ingreso Simultáneo (1.1.1.2 vs 4.1.5 y 8.1.2 vs 8.1.5)
        SELECT cc_id, cc_cuentapuntos, cc_nombre INTO v_cta_bancos 
        FROM contabilidad.catalogo_cuentas WHERE cc_cuentapuntos LIKE '1.1.1.2%' AND estatus_registro = 1 LIMIT 1;

        SELECT cc_id, cc_cuentapuntos, cc_nombre INTO v_cta_ingreso 
        FROM contabilidad.catalogo_cuentas WHERE cc_cuentapuntos LIKE '4.1.5%' AND estatus_registro = 1 LIMIT 1;

        SELECT cc_id, cc_cuentapuntos, cc_nombre INTO v_cta_presup_d 
        FROM contabilidad.catalogo_cuentas WHERE cc_cuentapuntos LIKE '8.1.2%' AND estatus_registro = 1 LIMIT 1;

        SELECT cc_id, cc_cuentapuntos, cc_nombre INTO v_cta_presup_h 
        FROM contabilidad.catalogo_cuentas WHERE cc_cuentapuntos LIKE '8.1.5%' AND estatus_registro = 1 LIMIT 1;

        v_asientos := jsonb_build_array(
            jsonb_build_object('renglon', 1, 'ambito', 'C', 'naturaleza', 'D', 'cuenta_puntos', v_cta_bancos.cc_cuentapuntos, 'cuenta_nombre', v_cta_bancos.cc_nombre, 'cargo', p_importe, 'abono', 0),
            jsonb_build_object('renglon', 2, 'ambito', 'C', 'naturaleza', 'H', 'cuenta_puntos', v_cta_ingreso.cc_cuentapuntos, 'cuenta_nombre', v_cta_ingreso.cc_nombre, 'cargo', 0, 'abono', p_importe),
            jsonb_build_object('renglon', 3, 'ambito', 'P', 'naturaleza', 'D', 'cuenta_puntos', v_cta_presup_d.cc_cuentapuntos, 'cuenta_nombre', v_cta_presup_d.cc_nombre, 'cargo', p_importe, 'abono', 0),
            jsonb_build_object('renglon', 4, 'ambito', 'P', 'naturaleza', 'H', 'cuenta_puntos', v_cta_presup_h.cc_cuentapuntos, 'cuenta_nombre', v_cta_presup_h.cc_nombre, 'cargo', 0, 'abono', p_importe)
        );
        v_suma_debe := p_importe * 2;
        v_suma_haber := p_importe * 2;
    END IF;

    RETURN jsonb_build_object(
        'error', 0,
        'mensaje', 'Pre-póliza evaluada exitosamente desde la Matriz Oficial CONAC.',
        'data', jsonb_build_object(
            'subtipo_tramite_id', p_subtipo_tramite_id,
            'nombre_subtipo', v_subtipo.nombre_subtipo,
            'es_borrador', p_es_borrador,
            'cuadrada', (v_suma_debe = v_suma_haber),
            'total_debe', v_suma_debe,
            'total_haber', v_suma_haber,
            'diferencia', (v_suma_debe - v_suma_haber),
            'asientos', v_asientos
        )
    );
EXCEPTION WHEN OTHERS THEN
    RETURN jsonb_build_object(
        'error', -2,
        'mensaje', 'Error técnico al calcular pre-póliza: ' || SQLERRM,
        'data', NULL
    );
END;
$$;

7 Reglas de Negocio de Pre-pólizas
RN-PREP-01 · Persistencia de Pre-póliza al Guardar Borrador

Al guardar un ingreso en estatus BORRADOR, el sistema no solo almacena los datos de cabecera; también guarda los renglones de la pre-póliza resuelta en ingresos.ingreso_prepoliza_detalles. Al reabrir el borrador, el pre-asiento ya se encuentra visible y cuadrado.

RN-PREP-02 · Tolerancia Cero al Descuadre

La suma de importes al Debe debe ser idéntica a la suma de importes al Haber tanto en el ámbito patrimonial como en el presupuestario. Cualquier diferencia en centavos bloquea la formalización del trámite.
