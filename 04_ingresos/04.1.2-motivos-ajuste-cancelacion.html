04.1.2

Motivos de ajuste o cancelación

Catálogo institucional de control y auditoría que estandariza las causas por las cuales se corrige, cancela, revierte o reclasifica una operación de ingreso, sustituyendo las notas de texto libre por tipificaciones trazables ante auditorías.

Pendiente de desarrollo Análisis funcional canónico (DOC-08) Responsable: Daryl
📌 Control Interno e Inmutabilidad Institucional

Este catálogo erradica la debilidad de control interno que representaba permitir notas libres arbitrarias para anular o alterar cifras de recaudación. Ningún usuario puede anular un recibo o desvincular un depósito sin seleccionar un motivo formal.

Principio de Inmutabilidad: Ningún ajuste o cancelación elimina físicamente registros contables. Cada motivo seleccionado detona un contramovimiento auditable que queda asentado con usuario, fecha, hora y justificación técnica.

1 Descripción General

El catálogo 04.1.2 Motivos de ajuste o cancelación constituye la salvaguarda de gobernanza de datos en el subsistema de ingresos. Siempre que un analista o cajero requiera realizar una enmienda sobre un recibo de ingreso, un depósito aplicado o una distribución presupuestaria, el sistema le exigirá seleccionar obligatoriamente un motivo catalogado.

Cada motivo tipificado define el nivel de severidad de la enmienda (informativa, de control o crítica), determina si se requiere autorización jerárquica de la Jefatura de Tesorería o Contabilidad, y especifica si la corrección exige detonar una póliza contable de reverso o una reclasificación presupuestaria.

2 Objetivo y Alcance

Objetivo: Estandarizar y auditar las causales de modificación sobre los registros de ingresos, erradicando la discrecionalidad y asegurando que cada ajuste mantenga una explicación documental tipificada ante auditorías internas y externas (ORFIS).

Dentro del Alcance Fuera del Alcance
  • Catálogo estandarizado de 12 motivos institucionales de corrección y anulación.
  • Niveles de severidad diferenciados (Informativa, Control, Crítica).
  • Banderas de control de autorización jerárquica obligatoria.
  • Tipificación de afectación contable/presupuestaria asociada.
  • Obligatoriedad de selección en formularios de anulación en 04.2.1 y 04.3.1.
  • Baja lógica inmutable (estatus_registro = 0).
  • Borrado físico de registros de base de datos (estrictamente prohibido).
  • Captura de justificaciones sin motivo catalogado previo.
  • Ajustes contables manuales libres fuera de la Matriz Oficial (03.1.2).

6 Procedimientos Almacenados (Stored Procedures)

Gobernanza transaccional en PostgreSQL bajo convención SECURITY DEFINER, SET search_path y respuesta estándar JSONB.

6.1. Procedimiento LEER (ingresos.fn_leer_motivos_ajuste)

CREATE OR REPLACE FUNCTION ingresos.fn_leer_motivos_ajuste(
    p_usuario VARCHAR,
    p_solo_activos BOOLEAN DEFAULT TRUE,
    p_severidad VARCHAR DEFAULT NULL
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = ingresos, config, public
AS $$
DECLARE
    v_data JSONB;
BEGIN
    SELECT jsonb_agg(
        jsonb_build_object(
            'motivo_id', m.motivo_id,
            'clave', m.clave,
            'nombre', m.nombre,
            'descripcion', m.descripcion,
            'nivel_severidad', m.nivel_severidad,
            'requiere_autorizacion', m.requiere_autorizacion,
            'rol_autorizador', m.rol_autorizador,
            'genera_contramovimiento', m.genera_contramovimiento,
            'estatus_registro', m.estatus_registro
        ) ORDER BY m.motivo_id
    )
    INTO v_data
    FROM ingresos.cat_motivos_ajuste m
    WHERE (NOT p_solo_activos OR m.estatus_registro = 1)
      AND (p_severidad IS NULL OR m.nivel_severidad = p_severidad);

    RETURN jsonb_build_object(
        'error', 0,
        'mensaje', 'Motivos de ajuste recuperados exitosamente.',
        'data', COALESCE(v_data, '[]'::jsonb)
    );
EXCEPTION WHEN OTHERS THEN
    RETURN jsonb_build_object('error', -2, 'mensaje', 'Error al consultar motivos: ' || SQLERRM, 'data', NULL);
END;
$$;

6.2. Procedimiento CRUD (ingresos.fn_crud_motivos_ajuste)

CREATE OR REPLACE FUNCTION ingresos.fn_crud_motivos_ajuste(
    p_accion VARCHAR,
    p_usuario VARCHAR,
    p_payload JSONB
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = ingresos, config, public
AS $$
DECLARE
    v_id BIGINT;
BEGIN
    IF p_accion = 'CREAR' THEN
        INSERT INTO ingresos.cat_motivos_ajuste (
            clave, nombre, descripcion, nivel_severidad,
            requiere_autorizacion, rol_autorizador, genera_contramovimiento,
            estatus_registro, usuario_c, fecha_c
        ) VALUES (
            UPPER(TRIM(p_payload->>'clave')),
            TRIM(p_payload->>'nombre'),
            TRIM(p_payload->>'descripcion'),
            p_payload->>'nivel_severidad',
            (p_payload->>'requiere_autorizacion')::BOOLEAN,
            p_payload->>'rol_autorizador',
            (p_payload->>'genera_contramovimiento')::BOOLEAN,
            1, p_usuario, CURRENT_TIMESTAMP
        ) RETURNING motivo_id INTO v_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Motivo creado exitosamente.', 'data', jsonb_build_object('motivo_id', v_id));

    ELSIF p_accion = 'EDITAR' THEN
        v_id := (p_payload->>'motivo_id')::BIGINT;
        UPDATE ingresos.cat_motivos_ajuste SET
            nombre                  = TRIM(p_payload->>'nombre'),
            descripcion             = TRIM(p_payload->>'descripcion'),
            nivel_severidad         = p_payload->>'nivel_severidad',
            requiere_autorizacion   = (p_payload->>'requiere_autorizacion')::BOOLEAN,
            rol_autorizador         = p_payload->>'rol_autorizador',
            genera_contramovimiento = (p_payload->>'genera_contramovimiento')::BOOLEAN,
            usuario_m               = p_usuario,
            fecha_m                 = CURRENT_TIMESTAMP
        WHERE motivo_id = v_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Motivo actualizado.', 'data', jsonb_build_object('motivo_id', v_id));

    ELSIF p_accion = 'CAMBIAR_ESTATUS' THEN
        v_id := (p_payload->>'motivo_id')::BIGINT;
        UPDATE ingresos.cat_motivos_ajuste SET
            estatus_registro = (p_payload->>'estatus_registro')::SMALLINT,
            usuario_m        = p_usuario,
            fecha_m          = CURRENT_TIMESTAMP
        WHERE motivo_id = v_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Estatus actualizado.', 'data', jsonb_build_object('motivo_id', v_id));
    END IF;

    RETURN jsonb_build_object('error', -1, 'mensaje', 'Acción no soportada: ' || p_accion, 'data', NULL);
END;
$$;

// NestJS Controller: MotivosAjusteIngresoController
@ApiTags('04.1.2 Motivos de Ajuste o Cancelación')
@Controller('api/v1/ingresos/motivos-ajuste')
@UseGuards(JwtAuthGuard, RolesGuard)
export class MotivosAjusteIngresoController {
  constructor(private readonly service: MotivosAjusteService) {}

  @Get()
  @ApiOperation({ summary: 'Listar motivos institucionales de ajuste o cancelación' })
  async listar(@CurrentUser() user: UserSession, @Query('severidad') sev?: string) {
    return this.service.leer(user, sev);
  }

  @Post()
  @ApiOperation({ summary: 'Registrar nuevo motivo de ajuste' })
  async crear(@CurrentUser() user: UserSession, @Body() dto: CreateMotivoDto) {
    return this.service.crear(user, dto);
  }

  @Put(':id')
  @ApiOperation({ summary: 'Actualizar configuración de motivo' })
  async actualizar(@Param('id') id: string, @CurrentUser() user: UserSession, @Body() dto: UpdateMotivoDto) {
    return this.service.actualizar(user, BigInt(id), dto);
  }

  @Patch(':id/estatus')
  @ApiOperation({ summary: 'Cambiar estatus (Baja lógica)' })
  async cambiarEstatus(@Param('id') id: string, @CurrentUser() user: UserSession, @Body() dto: EstatusDto) {
    return this.service.cambiarEstatus(user, BigInt(id), dto.estatus_registro);
  }
}
8 Reglas de Negocio
RN-MOT-01 · Obligatoriedad Estricta en Modales de Cancelación

El selector de Motivo es de captura forzosa en cualquier acción de cancelación en 04.2.1 o desvinculación bancaria en 04.3.1. El sistema deshabilita el botón de confirmación si no se ha elegido un motivo válido.

RN-MOT-02 · Firma Obligatoria en Severidad Crítica

Los motivos con nivel_severidad = 'CRITICA' (ej. REG_DUPLICADO, CRI_INCORRECTO) no surten efecto inmediato: quedan en estatus SOLICITUD_CANCELACION hasta ser autorizados por la Jefatura facultada.
