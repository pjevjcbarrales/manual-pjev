09.5.1

Configuración Server-Side y Requerimientos de Infraestructura

Guía técnica y de arquitectura para la implementación del backend de archivos en NestJS, almacenamiento desacoplado (NAS, MinIO, S3), seguridad de streaming, base de datos PostgreSQL y requerimientos de escáneres masivos para recopiladores contables.

Guía Técnica de Servidor Backend & Storage (DOC-08) NOM-151 / MinIO / PostgreSQL
⚙️ Desacoplamiento de Almacenamiento e Ingesta Segura

El subsistema de archivos nunca almacena archivos binarios dentro de PostgreSQL como campos BYTEA o BLOB. La base de datos únicamente gestiona metadatos, índices, hashes SHA-256 y relaciones polimórficas.

Los binarios físicos se administran a través del patrón Driver de Almacenamiento Desacoplado (`IFileStorageDriver`), permitiendo alternar de forma transparente entre un disco local/NAS institucional, un clúster local MinIO (S3-compatible) o una nube privada gubernamental sin modificar una sola línea de código del sistema.

1 Requerimientos de Infraestructura y Hardware

Para soportar el escaneo masivo del archivo contable histórico y corriente del Poder Judicial, se estipulan los siguientes requerimientos:

Componente Especificación Mínima Especificación Recomendada (Producción PJEV)
Almacenamiento Físico NAS institucional de 4 TB en RAID 5. SAN / Clúster MinIO distribuido de 16 TB con respaldo en modo WORM (Write Once Read Many).
Servidor de Aplicaciones (NestJS) 4 vCPUs, 8 GB RAM, disco SSD NVMe para cache temporal de subida. 8 vCPUs, 16 GB RAM, SSD NVMe clase empresarial con streaming I/O sin retención en memoria.
Red Institucional Gigabit Ethernet (1 Gbps) LAN en juzgados y oficinas. Enlace dedicado de 10 Gbps entre Servidor de Aplicaciones y Storage MinIO/NAS.
Escáneres de Producción Escáner departamental dúplex (40 ppm) con alimentador automático (ADF). Escáneres masivos de alta velocidad (80-120 ppm) Fujitsu/Canon con soporte para hojas separadoras con código QR/Barras y hot-folders SMB/FTP.
2 Requerimientos y Configuración de PostgreSQL

La base de datos PostgreSQL requiere habilitar las extensiones criptográficas para validar hashes de integridad y generar identificadores universales únicos:

-- Extensiones obligatorias en PostgreSQL 15+
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE EXTENSION IF NOT EXISTS "pgcrypto";

-- Esquema transversal dedicado
CREATE SCHEMA IF NOT EXISTS archivos;
GRANT USAGE ON SCHEMA archivos TO siaf_app;

-- Tablespace opcional para índices pesados de archivos
-- ALTER TABLE archivos.documento SET TABLESPACE ts_archivos_indices;
3 Configuración Backend (NestJS + Prisma)

El backend implementa la interfaz canónica de almacenamiento desacoplado:

// Interfaz de abstracción (src/archivos/interfaces/file-storage-driver.interface.ts)
export interface IFileStorageDriver {
  upload(fileStream: NodeJS.ReadableStream, relativePath: string): Promise<{ ruta_storage: string; tamanio_bytes: number }>;
  getStream(relativePath: string): Promise;
  delete(relativePath: string): Promise;
  exists(relativePath: string): Promise;
}

Variables de entorno obligatorias en el archivo .env:

# Configuración del Motor de Archivos SIAF-PJEV
STORAGE_DRIVER=minio               # Opciones: 'local', 'minio', 's3'
STORAGE_LOCAL_BASE_PATH=/mnt/storage_pjev/archivos/
STORAGE_MAX_FILE_SIZE_MB=30        # Límite general por archivo

# Credenciales MinIO / S3 Institucional
MINIO_ENDPOINT=minio.pjev.gob.mx
MINIO_PORT=9000
MINIO_USE_SSL=true
MINIO_ACCESS_KEY=pjev_siaf_admin
MINIO_SECRET_KEY=clave_super_segura_2026
MINIO_BUCKET_NAME=siaf-expedientes-digitales

# Integración Prestador de Certificación NOM-151 (PSC)
PSC_NOM151_API_URL=https://api.psc-acreditado.gob.mx/v1/timestamp
PSC_NOM151_API_KEY=token_acreditacion_secretaria_economia_2026

Pipeline de seguridad en subida de archivos (NestJS Interceptor):

  • Validación de Magic Bytes: Inspección de los primeros bytes reales del binario mediante la librería file-type para bloquear scripts maliciosos disfrazados de PDF o XML.
  • Cálculo en Stream de SHA-256: El resumen criptográfico se genera conforme el flujo de bytes entra al servidor, sin almacenar buffers pesados en la memoria RAM de Node.js.
  • Estructura de Almacenamiento en Disco: Particionamiento por año y mes con nombre UUID sanitizado:
    {BUCKET}/{AÑO}/{MES}/{UUID_DOCUMENTO}/original.{ext}
  • Headers de Visualización Segura:
    Content-Disposition: inline; filename="expediente.pdf"
    X-Content-Type-Options: nosniff
    Content-Security-Policy: default-src 'none'
