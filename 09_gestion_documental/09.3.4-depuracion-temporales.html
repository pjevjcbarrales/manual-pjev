09.3.4

Depuración Automática de Archivos Temporales

Proceso batch automatizado (Garbage Collector nocturno) para la detección y purga segura de archivos temporales huérfanos con más de 24 horas de antigüedad que nunca fueron consolidados en un trámite en firme del SIAF-PJEV.

Pendiente de desarrollo Mantenimiento y Storage (DOC-08) Cron Batch Nocturno
🧹 Higiene de Almacenamiento y Optimización de Disco

Cuando un usuario abre un formulario de alta (ej. Afectación de Gasto o Registro de Ingreso) y sube documentos antes de guardar el encabezado, estos se almacenan provisionalmente con es_temporal = TRUE vinculados a un ticket de sesión.

Si el usuario cancela la captura, pierde la conexión o cierra la pestaña, los archivos quedan huérfanos. Este proceso se ejecuta todas las noches a las 02:00 hrs para purgar el almacenamiento físico (MinIO/NAS) y deshabilitar los registros en base de datos, evitando fugas de almacenamiento.

1 Descripción General

El módulo 09.3.4 Depuración de Temporales previene la acumulación silenciosa de archivos basura sin comprometer en ningún momento los expedientes consolidados del Poder Judicial:

  • Ventana de Gracia Transaccional: Todo archivo temporal dispone de 24 horas de vigencia para que el usuario concluya su trámite.
  • Doble Purga (Base de Datos + Almacenamiento):
    1. El SP localiza los registros huérfanos y los marca con estatus_registro = 0.
    2. El servicio NestJS invoca IFileStorageDriver.delete(ruta_storage) para liberar los bloques físicos en el disco institucional.
  • Monitoreo y Forzado Manual: Los administradores pueden consultar el volumen de temporales activos y forzar una depuración inmediata si el almacenamiento alcanza umbrales de alerta.
2 Servicios y Procedimientos Canónicos
-- Stored Procedure invocado por el Cron nocturno de NestJS
CREATE OR REPLACE FUNCTION archivos.fn_depurar_archivos_temporales()
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = archivos, public
AS $$
DECLARE
    v_total_depurados INT;
    v_bytes_liberados BIGINT;
BEGIN
    WITH eliminados AS (
        UPDATE archivos.documento
        SET estatus_registro = 0,
            usuario_m = 'JOB_GARBAGE_COLLECTOR',
            fecha_m = clock_timestamp()
        WHERE es_temporal = TRUE 
          AND fecha_c < (clock_timestamp() - INTERVAL '24 hours')
          AND estatus_registro = 1
        RETURNING id, tamanio_bytes, ruta_storage
    )
    SELECT COUNT(*), COALESCE(SUM(tamanio_bytes), 0)
    INTO v_total_depurados, v_bytes_liberados
    FROM eliminados;

    RETURN jsonb_build_object(
        'error', 0,
        'mensaje', 'Depuración de archivos temporales concluida.',
        'data', jsonb_build_object(
            'total_depurados', v_total_depurados,
            'megabytes_liberados', ROUND(v_bytes_liberados / (1024.0 * 1024.0), 2)
        )
    );
END;
$$;
// Cron Job en NestJS (archivos.task.ts)
@Injectable()
export class ArchivosTaskService {
  constructor(
    private readonly prisma: PrismaService,
    @Inject('FILE_STORAGE_DRIVER') private readonly storage: IFileStorageDriver
  ) {}

  @Cron('0 2 * * *') // Todas las madrugadas a las 02:00 hrs
  async purgaNocturnaTemporales() {
    // 1. Obtener lista de rutas de almacenamiento a eliminar físicamente
    const huerfanos = await this.prisma.$queryRaw`
      SELECT id, ruta_storage FROM archivos.documento
      WHERE es_temporal = TRUE AND fecha_c < (NOW() - INTERVAL '24 hours') AND estatus_registro = 1
    `;

    // 2. Eliminar del Storage (MinIO / NAS)
    for (const doc of huerfanos) {
      await this.storage.delete(doc.ruta_storage);
    }

    // 3. Ejecutar SP de actualización en base de datos
    await this.prisma.$queryRaw`SELECT archivos.fn_depurar_archivos_temporales();`;
  }
}
3 Interfaz de Monitoreo de Almacenamiento
09.3.4 Consola de Monitoreo y Depuración de Temporales Higiene de Storage
Regla de Aislamiento: Ningún documento que cuente con es_temporal = FALSE o que esté vinculado a una entidad definitiva puede ser alcanzado por este proceso. 2. Frecuencia del Cron: La tarea programada de NestJS se ejecuta de manera silenciosa a las 02:00 hrs todos los días del año. 3. Sincronización Física y Lógica: Si la eliminación en el driver de almacenamiento (MinIO/NAS) falla, la base de datos no desactiva el registro y genera una alerta técnica en el log del sistema para evitar archivos fantasma. 4. Bitácora de Auditoría: Cada ciclo de depuración registra la cantidad de archivos purgados y el total de bytes liberados en la bitácora institucional.
