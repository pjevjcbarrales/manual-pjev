09.1.1

Cuadro General de Clasificación Archivística (CGCA)

Instrumento técnico de control y consulta archivística que codifica de forma jerárquica las funciones institucionales del Poder Judicial del Estado de Veracruz en Fondo, Subfondo, Sección, Serie y Subserie, conforme a la Ley General de Archivos y lineamientos del AGN.

Pendiente de desarrollo Análisis funcional canónico (DOC-08) Ley General de Archivos Art. 13 SIAF-PJEV Transversal
🏛️ Mandato de Ley: Instrumento de Control Archivístico Obligatorio

Conforme a los Artículos 13 y 14 de la Ley General de Archivos (LGA) y la Ley de Archivos del Estado de Veracruz, todo sujeto obligado debe contar de manera obligatoria con un Cuadro General de Clasificación Archivística (CGCA) validado institucionalmente.

En el SIAF-PJEV, ningún documento puede ser almacenado de forma huérfana o descontextualizada. Todo archivo registrado hereda forzosamente una clave de clasificación del CGCA que define su procedencia funcional y vincula sus plazos de retención con el Catálogo de Disposición Documental (CADIDO).

1 Descripción General

El catálogo 09.1.1 Cuadro General de Clasificación Archivística (CGCA) estructura lógicamente el acervo documental producido y recibido por el Poder Judicial del Estado de Veracruz. Modela las relaciones jerárquicas desde la máxima entidad institucional hasta las agrupaciones documentales específicas:

FONDO: PODER JUDICIAL DEL ESTADO DE VERACRUZ (PJEV)
  └── SUBFONDO: Órgano de Administración / Tribunal Superior de Justicia
      └── SECCIÓN: 1S Recursos Financieros / 2S Recursos Materiales / 3S Recursos Humanos
          └── SERIE: 1S.01 Pólizas Contables y Presupuestales
              └── SUBSERIE: 1S.01.01 Pólizas de Egresos / 1S.01.02 Pólizas de Ingresos

Esta codificación se convierte en la llave de indexación primaria para los motores de búsqueda transversal tipo DocuWare (*File Cabinet*), permitiendo localizar cualquier documento por su procedencia administrativa.

2 Objetivo y Alcance

Objetivo: Administrar el padrón oficial y jerárquico de series y subseries archivísticas del PJEV, garantizando su disponibilidad para la indexación automática en formularios de negocio y el cálculo de plazos de vigencia legal.

Dentro del Alcance Fuera del Alcance
  • Catálogo CRUD de códigos jerárquicos del CGCA (Fondo, Subfondo, Sección, Serie, Subserie).
  • Validación de unicidad de clave alfanumérica institucional (ej. PJEV-DGA-RF-1S.01).
  • Asociación obligatoria de series y subseries al CADIDO (09.1.2).
  • Filtrado por estatus activo e inactivo con soft-delete estricto.
  • Consumo como selector transversal en componentes <EntityFiles />.
  • Captura de documentos individuales (se realiza en 09.2.2 y formularios SIAF).
  • Definición de valores documentales y plazos de guarda (residen en CADIDO 09.1.2).
  • Expedición de actas de baja o dictámenes de destino final (residen en 09.3.3).

6 Stored Procedures Canónicos (PostgreSQL)

Siguiendo los estándares del SIAF-PJEV, la lógica de lectura y modificación reside en PostgreSQL bajo SECURITY DEFINER y retorno JSONB estandarizado.

-- SP 1: archivos.fn_leer_cgca
CREATE OR REPLACE FUNCTION archivos.fn_leer_cgca(
    p_filtros JSONB DEFAULT '{}'::jsonb
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = archivos, public
AS $$
DECLARE
    v_id INT;
    v_codigo VARCHAR(50);
    v_seccion VARCHAR(100);
    v_resultado JSONB;
BEGIN
    v_id := (p_filtros->>'cgca_id')::int;
    v_codigo := p_filtros->>'cgca_codigo';
    v_seccion := p_filtros->>'seccion';

    SELECT COALESCE(jsonb_agg(row_to_json(r)), '[]'::jsonb)
    INTO v_resultado
    FROM (
        SELECT 
            c.cgca_id,
            c.cgca_codigo,
            c.fondo,
            c.subfondo,
            c.seccion,
            c.serie,
            c.subserie,
            c.descripcion,
            c.estatus_registro,
            c.usuario_c,
            c.fecha_c,
            c.usuario_m,
            c.fecha_m,
            (
                SELECT COUNT(*)::int
                FROM archivos.documento d
                WHERE d.cgca_codigo = c.cgca_codigo AND d.estatus_registro = 1
            ) AS total_documentos_asociados
        FROM archivos.cgca_catalogo c
        WHERE c.estatus_registro = COALESCE((p_filtros->>'estatus_registro')::smallint, 1)
          AND (v_id IS NULL OR c.cgca_id = v_id)
          AND (v_codigo IS NULL OR c.cgca_codigo ILIKE '%' || v_codigo || '%')
          AND (v_seccion IS NULL OR c.seccion = v_seccion)
        ORDER BY c.seccion ASC, c.serie ASC, c.subserie ASC
    ) r;

    RETURN jsonb_build_object('error', 0, 'mensaje', 'OK', 'data', v_resultado);
EXCEPTION WHEN OTHERS THEN
    RETURN jsonb_build_object('error', -2, 'mensaje', 'Error en fn_leer_cgca: ' || SQLERRM, 'data', '[]'::jsonb);
END;
$$;
-- SP 2: archivos.fn_crud_cgca
CREATE OR REPLACE FUNCTION archivos.fn_crud_cgca(
    p_operacion VARCHAR(20),
    p_datos JSONB
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = archivos, public
AS $$
DECLARE
    v_id INT;
    v_codigo VARCHAR(50);
    v_usuario VARCHAR(50);
BEGIN
    v_usuario := COALESCE(p_datos->>'usuario', 'SISTEMA');

    IF p_operacion = 'INSERT' THEN
        v_codigo := UPPER(TRIM(p_datos->>'cgca_codigo'));

        -- Validar unicidad de clave
        IF EXISTS (SELECT 1 FROM archivos.cgca_catalogo WHERE cgca_codigo = v_codigo) THEN
            RETURN jsonb_build_object('error', -1, 'mensaje', 'La clave de clasificación ya existe: ' || v_codigo, 'data', null);
        END IF;

        INSERT INTO archivos.cgca_catalogo (
            cgca_codigo, fondo, subfondo, seccion, serie, subserie, descripcion,
            estatus_registro, usuario_c, fecha_c
        ) VALUES (
            v_codigo,
            COALESCE(p_datos->>'fondo', 'PODER JUDICIAL DEL ESTADO DE VERACRUZ'),
            p_datos->>'subfondo',
            UPPER(TRIM(p_datos->>'seccion')),
            UPPER(TRIM(p_datos->>'serie')),
            NULLIF(UPPER(TRIM(p_datos->>'subserie')), ''),
            p_datos->>'descripcion',
            1, v_usuario, clock_timestamp()
        ) RETURNING cgca_id INTO v_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Serie archivística creada exitosamente.', 'data', jsonb_build_object('cgca_id', v_id));

    ELSIF p_operacion = 'UPDATE' THEN
        v_id := (p_datos->>'cgca_id')::int;

        UPDATE archivos.cgca_catalogo
        SET subfondo = p_datos->>'subfondo',
            seccion = UPPER(TRIM(p_datos->>'seccion')),
            serie = UPPER(TRIM(p_datos->>'serie')),
            subserie = NULLIF(UPPER(TRIM(p_datos->>'subserie')), ''),
            descripcion = p_datos->>'descripcion',
            usuario_m = v_usuario,
            fecha_m = clock_timestamp()
        WHERE cgca_id = v_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Serie archivística actualizada exitosamente.', 'data', jsonb_build_object('cgca_id', v_id));

    ELSIF p_operacion = 'DESACTIVAR' THEN
        v_id := (p_datos->>'cgca_id')::int;

        -- Regla de integridad: No desactivar si tiene documentos activos
        IF EXISTS (
            SELECT 1 FROM archivos.documento d 
            JOIN archivos.cgca_catalogo c ON d.cgca_codigo = c.cgca_codigo
            WHERE c.cgca_id = v_id AND d.estatus_registro = 1
        ) THEN
            RETURN jsonb_build_object('error', -1, 'mensaje', 'No es posible desactivar una serie con expedientes o documentos activos asociados.', 'data', null);
        END IF;

        UPDATE archivos.cgca_catalogo
        SET estatus_registro = 0,
            usuario_m = v_usuario,
            fecha_m = clock_timestamp()
        WHERE cgca_id = v_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Serie archivística desactivada.', 'data', jsonb_build_object('cgca_id', v_id));

    ELSE
        RETURN jsonb_build_object('error', -1, 'mensaje', 'Operación no válida: ' || p_operacion, 'data', null);
    END IF;

EXCEPTION WHEN OTHERS THEN
    RETURN jsonb_build_object('error', -2, 'mensaje', 'Error en fn_crud_cgca: ' || SQLERRM, 'data', null);
END;
$$;
