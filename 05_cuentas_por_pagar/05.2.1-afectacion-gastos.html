05.2.1

Solicitud-comprobación de recurso (Orden de pago)

Captura y revisión de trámites presupuestales, partidas, expediente y póliza de devengo.

1 Descripción general

La Solicitud-comprobación de recurso registra un trámite presupuestal de Tesorería. El capturista selecciona el procedimiento, guarda el encabezado, captura las partidas y reúne el expediente digital. El revisor consulta los soportes y la previsualización contable antes de resolver el trámite.

La pantalla 05.2.1 consulta los grupos presupuestales 1 a 3. El grupo 4 se opera en 05.2.2 mediante servicios CxP compartidos. La autorización presupuestal genera o recupera la póliza de devengo en CxP. En el diseño, el estado Contabilizada requiere confirmar la afectación de esa póliza. La autorización y ejecución del pago continúan en sus procesos correspondientes.

El diccionario muestra el diseño final. Las fechas de auditoría existentes son de tipo timestamp sin zona. Los campos señalados para revisión siguen formando parte del contrato. La migración del estado del encabezado, las llaves e índice de Partidas y los nombres de columnas está pendiente. El SQL instalado documenta el contrato vigente.

Definición SQL instalada de fn_leer_afectacion_encabezado 
CREATE OR REPLACE FUNCTION cxp.fn_leer_afectacion_encabezado(p_ejercicio_fiscal integer, p_ag_id uuid DEFAULT NULL::uuid, p_estatus character varying DEFAULT NULL::character varying, p_tipo_pago integer DEFAULT NULL::integer, p_fecha_desde date DEFAULT NULL::date, p_fecha_hasta date DEFAULT NULL::date, p_page integer DEFAULT 1, p_limit integer DEFAULT 50)
     RETURNS jsonb
     LANGUAGE plpgsql
     STABLE
     SET search_path TO 'cxp', 'contabilidad', 'config', 'pg_catalog'
    AS $function$
    DECLARE
      v_data jsonb;
      v_total bigint;
      v_offset integer;
    BEGIN
      IF p_ejercicio_fiscal IS NULL THEN
        RETURN jsonb_build_object(
          'cod_resultado', -1,
          'msg_resultado', 'El ejercicio fiscal es obligatorio.',
          'data', '[]'::jsonb
        );
      END IF;

      v_offset := (greatest(p_page, 1) - 1) * least(greatest(p_limit, 1), 200);

      SELECT count(*) INTO v_total
        FROM cxp.afectaciones_gasto a
       WHERE a.ejercicio_fiscal = p_ejercicio_fiscal
         AND a.estatus_registro = 1
         AND (p_ag_id IS NULL OR a.ag_id = p_ag_id)
         AND (p_estatus IS NULL OR a.estatus_workflow = p_estatus)
         AND (p_tipo_pago IS NULL OR coalesce(a.matriz_grupo_id, a.tipo_pago) = p_tipo_pago)
         AND (p_fecha_desde IS NULL OR a.fecha_elaboracion >= p_fecha_desde)
         AND (p_fecha_hasta IS NULL OR a.fecha_elaboracion <= p_fecha_hasta);

      SELECT coalesce(jsonb_agg(to_jsonb(q)), '[]'::jsonb) INTO v_data
        FROM (
          SELECT
            a.ag_id AS id,
            a.ag_id,
            a.ejercicio_fiscal,
            a.folio,
            coalesce(a.matriz_grupo_id, a.tipo_pago) AS tipo_pago,
            a.subtipo_pago,
            a.matriz_grupo_id,
            a.matriz_procedimiento_id,
            coalesce(proc.mgp_codigo, a.tipo_operacion, 'GASTO_DIRECTO_GENERAL') AS tipo_operacion,
            coalesce(proc.mgp_nombre, 'Pago Directo') AS tipo_tramite_desc,
            coalesce(
              proc.mgt_titulo,
              CASE coalesce(a.matriz_grupo_id, a.tipo_pago)
                WHEN 1 THEN 'Pago directo'
                WHEN 2 THEN 'Pago derivado de un pedido'
                WHEN 3 THEN 'Gasto a comprobar'
                WHEN 4 THEN 'No afecta presupuesto'
                ELSE 'Sin clasificar'
              END
            ) AS tipo_pago_desc,
            a.afecta_presupuesto,
            a.f_pedido_id,
            a.f_comprobacion_id,
            a.f_centro_costo_id,
            jsonb_build_object(
              'id', cc.cc_id,
              'clave', cc.cc_clave,
              'nombre', cc.cc_nombre
            ) AS organizacion,
            cc.cc_nombre AS centro_nombre,
            cc.cc_clave AS centro_clave,
            a.concepto,
            a.fecha_elaboracion,
            a.estatus_workflow,
            a.estatus_workflow AS estatus,
            coalesce(a.p_poliza_id, pol_cxp.p_id) AS p_poliza_id,
            CASE
              WHEN a.p_poliza_id IS NOT NULL OR pol_cxp.p_id IS NOT NULL THEN 'AFECTADA'
              ELSE 'PENDIENTE'
            END AS estatus_contabilidad,
            CASE
              WHEN pol.p_id IS NOT NULL THEN concat_ws('-', pol.p_tipo, nullif(pol.p_subtipo, ''), pol.p_numero)
              WHEN pol_cxp.p_id IS NOT NULL THEN concat_ws('-', pol_cxp.p_tipo, nullif(pol_cxp.p_subtipo, ''), pol_cxp.p_numero)
              ELSE NULL
            END AS poliza_contabilidad,
            CASE a.estatus_workflow
              WHEN 'BORRADOR' THEN 1
              WHEN 'ENVIADA' THEN 2
              WHEN 'APROBADA' THEN 3
              WHEN 'REGRESADA' THEN 4
              WHEN 'RECHAZADA' THEN 5
              WHEN 'CANCELADA' THEN 9
              ELSE 1
            END AS estatus_codigo,
            a.f_proveedor_id,
            a.f_empleado_id,
            a.f_ua_id,
            a.f_tercero_id,
            a.f_tercero_inst_id,
            a.f_bien_inmueble_id,
            coalesce(
              a.f_proveedor_id,
              a.f_empleado_id,
              a.f_ua_id,
              a.f_tercero_id,
              a.f_tercero_inst_id,
              a.f_bien_inmueble_id
            ) AS beneficiario_id,
            CASE
              WHEN a.f_proveedor_id IS NOT NULL THEN 'PROV:'
              WHEN a.f_empleado_id IS NOT NULL THEN 'EMP:'
              WHEN a.f_ua_id IS NOT NULL THEN 'UA:'
              WHEN a.f_tercero_id IS NOT NULL THEN 'TER:'
              WHEN a.f_tercero_inst_id IS NOT NULL THEN 'TINS:'
              WHEN a.f_bien_inmueble_id IS NOT NULL THEN 'INM:'
            END AS beneficiario_tipo,
            coalesce(
              prov.cp_razonsocial,
              prov.cp_nombre,
              emp.ce_nombre,
              bua.cua_nombre,
              ter.cb_nombre,
              tins.cti_nombre,
              inm.nombre_oficial,
              'Sin beneficiario'
            ) AS beneficiario_nombre,
            a.referencia,
            a.cuenta_contable_abono,
            a.importe_total_pago,
            coalesce(
              nullif((
                SELECT sum(d.importe_solicitado)
                  FROM cxp.afectaciones_gasto_detalles d
                 WHERE d.f_ag_id = a.ag_id
                   AND d.ejercicio_fiscal = a.ejercicio_fiscal
                   AND d.estatus_registro = 1
              ), 0),
              a.importe_total_pago,
              0
            ) AS importe_total,
            (
              SELECT count(*)
                FROM cxp.afectaciones_gasto_detalles d
               WHERE d.f_ag_id = a.ag_id
                 AND d.ejercicio_fiscal = a.ejercicio_fiscal
                 AND d.estatus_registro = 1
            ) AS n_detalles,
            (
              SELECT count(*)
                FROM cxp.afectaciones_gasto_cfdi c
               WHERE c.f_ag_id = a.ag_id
                 AND c.ejercicio_fiscal = a.ejercicio_fiscal
                 AND c.estatus_registro = 1

              'ELIMINAR',
              'CAPTURAR_PARTIDAS',
              'CAPTURAR_CFDI',
              'EXPEDIENTE_DIGITAL'

            a.usuario_c,
            a.fecha_c,
            a.usuario_m,
            a.fecha_m
          FROM cxp.afectaciones_gasto a
          LEFT JOIN config.catalogo_centros_costos cc
            ON cc.cc_id = a.f_centro_costo_id
          LEFT JOIN LATERAL (
            SELECT
              p.matriz_grupo_procedimiento_id,
              p.matriz_grupo_id,
              p.mgp_codigo,
              p.mgp_nombre,
              g.mgt_codigo,
              g.mgt_titulo
            FROM contabilidad.matriz_grupos_procedimiento p
            JOIN contabilidad.matriz_grupos_tramite g
              ON g.matriz_grupo_id = p.matriz_grupo_id
            WHERE g.mgt_ambito = 'E'
              AND (
                p.matriz_grupo_procedimiento_id = a.matriz_procedimiento_id
                OR p.mgp_codigo = a.tipo_operacion
                OR p.mgp_codigo_legado = a.tipo_operacion
              )
            ORDER BY
              CASE
                WHEN p.matriz_grupo_procedimiento_id = a.matriz_procedimiento_id THEN 0
                WHEN p.mgp_codigo = a.tipo_operacion THEN 1
                ELSE 2
              END,
              p.matriz_grupo_procedimiento_id
            LIMIT 1
          ) proc ON true
          LEFT JOIN config.catalogo_proveedores prov
            ON prov.cp_id = a.f_proveedor_id AND prov.estatus_registro = 1
          LEFT JOIN config.catalogo_empleados emp
            ON emp.ce_id = a.f_empleado_id AND emp.estatus_registro = 1
          LEFT JOIN config.catalogo_ua bua
            ON bua.cua_id = a.f_ua_id AND bua.estatus_registro = 1
          LEFT JOIN config.catalogo_terceros ter
            ON ter.cb_id = a.f_tercero_id AND ter.estatus_registro = 1
          LEFT JOIN config.catalogo_terceros_inst tins
            ON tins.cti_id = a.f_tercero_inst_id AND tins.estatus_registro = 1
          LEFT JOIN config.catalogo_bienes_inmuebles inm
            ON inm.inmueble_id = a.f_bien_inmueble_id AND inm.estatus_registro = 1
          LEFT JOIN contabilidad.poliza pol
            ON pol.p_id = a.p_poliza_id
           AND pol.p_ejercicio = a.ejercicio_fiscal
          LEFT JOIN LATERAL (
            SELECT cp.p_id, cp.p_tipo, cp.p_subtipo, cp.p_numero
              FROM cxp.poliza cp
             WHERE cp.p_ejercicio = a.ejercicio_fiscal
               AND cp.estatus_registro = 1
               AND cp.p_origen = 1
               AND cp.p_origen_id = abs(hashtext(a.ag_id::text))
             ORDER BY cp.p_id DESC
             LIMIT 1
          ) pol_cxp ON true
         WHERE a.ejercicio_fiscal = p_ejercicio_fiscal

           AND (p_estatus IS NULL OR a.estatus_workflow = p_estatus)
           AND (p_tipo_pago IS NULL OR coalesce(a.matriz_grupo_id, a.tipo_pago) = p_tipo_pago)
           AND (p_fecha_desde IS NULL OR a.fecha_elaboracion >= p_fecha_desde)
           AND (p_fecha_hasta IS NULL OR a.fecha_elaboracion <= p_fecha_hasta)
         ORDER BY a.fecha_c ASC, a.folio ASC
         LIMIT least(greatest(p_limit, 1), 200)
        OFFSET v_offset
      ) q;

      RETURN jsonb_build_object(
        'cod_resultado', 0,

                    RETURN json_build_object('cod_resultado', -1, 'msg_resultado', 'Solo se pueden regresar afectaciones enviadas a revisión.', 'data', NULL);

                v_estatus_nuevo := 'REGRESADA';

            WHEN 'CANCELAR' THEN

           SET estatus_workflow = v_estatus_nuevo,
               usuario_m = v_usuario_limpio,
               fecha_m = v_fecha_real

            v_estatus_actual,
            v_estatus_nuevo,
            v_fecha_envio_final,
            v_fecha_real,
            v_usuario_limpio,
            nullif(btrim(p_observacion), '')
        );

        RETURN json_build_object(
            'cod_resultado', 0,
            'msg_resultado', CASE
              WHEN v_accion_limpia = 'APROBAR' AND (NOT v_afecta_presupuesto OR coalesce(v_matriz_grupo_id, 1) = 4)
                THEN 'Solicitud no presupuestal aprobada y turnada para dispersión bancaria.'

              ELSE format('Afectación procesada correctamente a estado %s.', v_estatus_nuevo)

             AND estatus_registro = 1

            'cod_resultado', 0,

            'data', json_build_object(
                'poliza_cxp_id', v_poliza_cxp_id,
                'tipo', v_tipo_poliza,
                'folio', v_folio_poliza,
                'movimientos', v_mov_orden
            )
        );
    END;

    DECLARE
      v_proc record;
      v_codigo varchar(40);
    BEGIN
      v_codigo := btrim(coalesce(nullif(btrim(NEW.tipo_operacion), ''), nullif(btrim(NEW.f_procedimiento_codigo), '')));

      IF v_codigo IS NULL AND NEW.matriz_procedimiento_id IS NULL THEN
        RAISE EXCEPTION USING ERRCODE = '23514', MESSAGE = 'El procedimiento de afectacion es obligatorio.';
      END IF;

      SELECT

        p.matriz_grupo_procedimiento_id::integer AS matriz_procedimiento_id,
        p.mgp_codigo,
        g.mgt_codigo,
        g.mgt_numero::smallint AS tipo_pago,
        g.afecta_presupuesto
      INTO v_proc
      FROM contabilidad.matriz_grupos_procedimiento p
      JOIN contabilidad.matriz_grupos_tramite g
        ON g.matriz_grupo_id = p.matriz_grupo_id
      WHERE g.mgt_ambito = 'E'

        AND g.estatus_registro = 1

          OR (v_codigo IS NOT NULL AND p.mgp_codigo = v_codigo)
          OR (v_codigo IS NOT NULL AND p.mgp_codigo_legado = v_codigo)
          OR (v_codigo = 'FONDOS_CUSTODIA' AND p.matriz_grupo_procedimiento_id = 403)
        )
      ORDER BY
        CASE
          WHEN NEW.matriz_procedimiento_id IS NOT NULL AND p.matriz_grupo_procedimiento_id = NEW.matriz_procedimiento_id THEN 0
          WHEN v_codigo IS NOT NULL AND p.mgp_codigo = v_codigo THEN 1
          WHEN (NEW.tipo_pago = 4 OR NEW.afecta_presupuesto = false) AND p.matriz_grupo_id = 4 THEN 2
          WHEN COALESCE(NEW.tipo_pago, 1) <> 4 AND COALESCE(NEW.afecta_presupuesto, true) = true AND p.matriz_grupo_id <> 4 THEN 2
          ELSE 3
        END,
        p.matriz_grupo_procedimiento_id
      LIMIT 1;

      IF NOT FOUND THEN
        RAISE EXCEPTION USING ERRCODE = '23514', MESSAGE = 'El procedimiento de afectacion no existe o no esta habilitado en la matriz v3.';
      END IF;

      NEW.matriz_grupo_id := v_proc.matriz_grupo_id;
      NEW.matriz_procedimiento_id := v_proc.matriz_procedimiento_id;
      NEW.f_grupo_codigo := v_proc.mgt_codigo;
      NEW.tipo_operacion := v_proc.mgp_codigo;
      NEW.f_procedimiento_codigo := v_proc.mgp_codigo;
      NEW.tipo_pago := v_proc.tipo_pago;
      NEW.afecta_presupuesto := v_proc.afecta_presupuesto;

      RETURN NEW;

Trazabilidad y minería de procesos

El registro instalado es cxp.afectaciones_historial. Identifica el trámite por UUID y ejercicio y registra acción, actor, estados, fecha real, fecha operativa y observación. Los intentos rechazados por las validaciones retornan antes de guardar una transición.

La propuesta transversal de eventos puede correlacionar revisión formal, envío, aprobación y resultado por UUID y ejercicio, y vincular la póliza de CxP y los documentos. El rol y los resultados rechazados son datos candidatos para la función genérica propuesta.

11 Afectación contable

PrevisualizaciónConsulta la clasificación y proyecta los movimientos. Permite ver la referencia de una póliza CxP ya generada.
Aprobación presupuestalLa función instalada genera o recupera la póliza PD en cxp.poliza y cxp.poliza_movtos. Usa la matriz inicial del procedimiento y busca la regla por partida y evento. La cabecera y sus movimientos se relacionan por la referencia de origen.
