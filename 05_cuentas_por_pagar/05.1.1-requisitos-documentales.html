05.1.1

Requisitos Documentales (Matriz Checklist de Soportes de Gasto)

Catálogo maestro y matriz de exigibilidad que tipifica los comprobantes fiscales, contratos, actas y formatos obligatorios que deben integrarse al expediente digital antes de autorizar y devengar cualquiera de los 12 procedimientos canónicos de gasto en el SIAF-PJEV.

Modo A — Catálogo Simple Parametrizado Fase 2: Ejecución del Gasto Gobierno del Expediente Digital Ruta Backend: /api/v1/cxp/requisitos-documentales
1 Descripción General

En la administración pública estatal, el reconocimiento contable y presupuestario del Devengado (LGCG Art. 4 Fracc. XVI) exige que el ente público cuente con el respaldo documental fidedigno que acredite la recepción conforme de los bienes, la prestación efectiva de los servicios o el cumplimiento de los términos de una comisión oficial. Históricamente, en el PJEV esta verificación se realizaba mediante revisiones manuales en papel descritas en el procedimiento "Recepción y revisión de gastos" de la Subdirección de Recursos Financieros.

El módulo 05.1.1 Requisitos Documentales traslada esta normatividad a una matriz relacional inteligente. Permite a los administradores del sistema parametrizar, por cada uno de los 12 procedimientos de afectación del gasto (NOMINA, ARRENDAMIENTO, SERVICIOS_BASICOS, COMPRA_PEDIDO, OBRA_PUBLICA, COMPROBACION_VIATICOS, etc.), qué documentos soporte son Obligatorios, Condicionales u Opcionales. Esta matriz alimenta automáticamente el componente SiafExpedienteDigitalMin en la captura de 05.2.1 Afectación del Gasto, impidiendo que un trámite avance en el workflow si no cuenta con el expediente digital íntegro y validado fiscalmente.

7 Procedimientos Almacenados (Stored Procedures)

Conforme al estándar arquitectónico SIAF-PJEV, la lógica de lectura, persistencia y validación del checklist reside en funciones PostgreSQL en el esquema cxp con SECURITY DEFINER, SET search_path y retorno JSONB unificado { "error": 0, "mensaje": "OK", "data": [...] }:

Función de Consulta: cxp.fn_leer_requisitos_documentales

Parámetro (IN)TipoDescripción
p_usuarioVARCHAR(50)Usuario activo de sesión.
p_ejercicioINTEGEREjercicio fiscal en curso.
p_buscarVARCHAR(100)Filtro de búsqueda por código o nombre (Opcional).
p_doc_idBIGINTID específico para detalle modal (Opcional).
p_procedimiento_codigoVARCHAR(40)Filtro para obtener la matriz de un procedimiento específico (Opcional).
p_estatusSMALLINT1 = Activos, 0 = Inactivos, NULL = Todos.
 
CREATE OR REPLACE FUNCTION cxp.fn_leer_requisitos_documentales(
    p_usuario VARCHAR,
    p_ejercicio INTEGER,
    p_buscar VARCHAR DEFAULT NULL,
    p_doc_id BIGINT DEFAULT NULL,
    p_procedimiento_codigo VARCHAR DEFAULT NULL,
    p_estatus SMALLINT DEFAULT 1
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = cxp, config, public
AS $$
DECLARE
    v_data JSONB;
BEGIN
    SELECT jsonb_agg(
        jsonb_build_object(
            'doc_id', d.doc_id,
            'doc_codigo', d.doc_codigo,
            'doc_nombre', d.doc_nombre,
            'doc_descripcion', d.doc_descripcion,
            'formato_permitido', d.formato_permitido,
            'tamano_max_mb', d.tamano_max_mb,
            'valida_sat', d.valida_sat,
            'valida_vigencia_dias', d.valida_vigencia_dias,
            'estatus_registro', d.estatus_registro,
            'requisitos_asociados', COALESCE((
                SELECT jsonb_agg(
                    jsonb_build_object(
                        'rps_id', r.rps_id,
                        'procedimiento_codigo', r.f_procedimiento_codigo,
                        'procedimiento_nombre', p.cpa_nombre,
                        'nivel_exigencia', r.nivel_exigencia,
                        'condicion_sql', r.condicion_sql,
                        'orden_visual', r.orden_visual
                    ) ORDER BY r.orden_visual
                )
                FROM cxp.requisitos_procedimiento_soporte r
                JOIN cxp.catalogo_procedimientos_afectacion p ON p.cpa_codigo = r.f_procedimiento_codigo
                WHERE r.f_doc_id = d.doc_id
                  AND r.estatus_registro = 1
                  AND (p_procedimiento_codigo IS NULL OR r.f_procedimiento_codigo = p_procedimiento_codigo)
            ), '[]'::jsonb)
        ) ORDER BY d.doc_codigo
    ) INTO v_data
    FROM cxp.catalogo_documentos_soporte d
    WHERE (p_estatus IS NULL OR d.estatus_registro = p_estatus)
      AND (p_doc_id IS NULL OR d.doc_id = p_doc_id)
      AND (p_buscar IS NULL OR (
          d.doc_codigo ILIKE '%' || p_buscar || '%' OR
          d.doc_nombre ILIKE '%' || p_buscar || '%'
      ))
      AND (p_procedimiento_codigo IS NULL OR EXISTS (
          SELECT 1 FROM cxp.requisitos_procedimiento_soporte r2
          WHERE r2.f_doc_id = d.doc_id
            AND r2.f_procedimiento_codigo = p_procedimiento_codigo
            AND r2.estatus_registro = 1
      ));

    RETURN jsonb_build_object(
        'error', 0,
        'mensaje', 'OK',
        'data', COALESCE(v_data, '[]'::jsonb)
    );
EXCEPTION WHEN OTHERS THEN
    RETURN jsonb_build_object('error', -2, 'mensaje', SQLERRM, 'data', NULL);
END;
$$;

Función Transaccional: cxp.fn_crud_requisitos_documentales

Parámetro (IN)TipoDescripción
p_accionSMALLINT1 = Alta, 2 = Modificación, 3 = Baja Lógica, 4 = Reactivar.
p_usuarioVARCHAR(50)Usuario responsable de la transacción.
p_ejercicioINTEGEREjercicio fiscal activo.
p_doc_idBIGINTID del documento (Requerido en acción 2, 3 y 4).
p_datosJSONBPayload con datos del documento y matriz de procedimientos.
 
CREATE OR REPLACE FUNCTION cxp.fn_crud_requisitos_documentales(
    p_accion SMALLINT,
    p_usuario VARCHAR,
    p_ejercicio INTEGER,
    p_doc_id BIGINT,
    p_datos JSONB
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = cxp, config, public
AS $$
DECLARE
    v_id BIGINT;
    v_item JSONB;
BEGIN
    -- 1 = ALTA
    IF p_accion = 1 THEN
        IF EXISTS (SELECT 1 FROM cxp.catalogo_documentos_soporte WHERE doc_codigo = UPPER(TRIM(p_datos->>'doc_codigo'))) THEN
            RETURN jsonb_build_object('error', -1, 'mensaje', 'El código de documento ya se encuentra registrado.');
        END IF;

        INSERT INTO cxp.catalogo_documentos_soporte (
            doc_codigo, doc_nombre, doc_descripcion, formato_permitido,
            tamano_max_mb, valida_sat, valida_vigencia_dias, estatus_registro,
            usuario_c, fecha_c
        ) VALUES (
            UPPER(TRIM(p_datos->>'doc_codigo')),
            TRIM(p_datos->>'doc_nombre'),
            p_datos->>'doc_descripcion',
            COALESCE(p_datos->>'formato_permitido', 'PDF'),
            COALESCE((p_datos->>'tamano_max_mb')::NUMERIC, 10.0),
            COALESCE((p_datos->>'valida_sat')::BOOLEAN, false),
            (p_datos->>'valida_vigencia_dias')::INTEGER,
            1, p_usuario, clock_timestamp()
        ) RETURNING doc_id INTO v_id;

        -- Registrar exigibilidad en procedimientos si viene en el payload
        IF p_datos ? 'procedimientos' THEN
            FOR v_item IN SELECT * FROM jsonb_array_elements(p_datos->'procedimientos') LOOP
                INSERT INTO cxp.requisitos_procedimiento_soporte (
                    f_procedimiento_codigo, f_doc_id, nivel_exigencia,
                    condicion_sql, orden_visual, estatus_registro, usuario_c
                ) VALUES (
                    v_item->>'procedimiento_codigo', v_id,
                    COALESCE(v_item->>'nivel_exigencia', 'OBLIGATORIO'),
                    v_item->>'condicion_sql',
                    COALESCE((v_item->>'orden_visual')::SMALLINT, 1),
                    1, p_usuario
                ) ON CONFLICT (f_procedimiento_codigo, f_doc_id) DO UPDATE
                SET nivel_exigencia = EXCLUDED.nivel_exigencia,
                    condicion_sql = EXCLUDED.condicion_sql,
                    orden_visual = EXCLUDED.orden_visual,
                    estatus_registro = 1, usuario_m = p_usuario, fecha_m = clock_timestamp();
            END LOOP;
        END IF;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Documento soporte registrado con éxito.', 'data', jsonb_build_object('doc_id', v_id));

    -- 2 = MODIFICACIÓN
    ELSIF p_accion = 2 THEN
        UPDATE cxp.catalogo_documentos_soporte SET
            doc_nombre = COALESCE(TRIM(p_datos->>'doc_nombre'), doc_nombre),
            doc_descripcion = COALESCE(p_datos->>'doc_descripcion', doc_descripcion),
            formato_permitido = COALESCE(p_datos->>'formato_permitido', formato_permitido),
            tamano_max_mb = COALESCE((p_datos->>'tamano_max_mb')::NUMERIC, tamano_max_mb),
            valida_sat = COALESCE((p_datos->>'valida_sat')::BOOLEAN, valida_sat),
            valida_vigencia_dias = (p_datos->>'valida_vigencia_dias')::INTEGER,
            usuario_m = p_usuario, fecha_m = clock_timestamp()
        WHERE doc_id = p_doc_id;

        -- Actualizar matriz si se proporciona
        IF p_datos ? 'procedimientos' THEN
            FOR v_item IN SELECT * FROM jsonb_array_elements(p_datos->'procedimientos') LOOP
                INSERT INTO cxp.requisitos_procedimiento_soporte (
                    f_procedimiento_codigo, f_doc_id, nivel_exigencia,
                    condicion_sql, orden_visual, estatus_registro, usuario_c
                ) VALUES (
                    v_item->>'procedimiento_codigo', p_doc_id,
                    COALESCE(v_item->>'nivel_exigencia', 'OBLIGATORIO'),
                    v_item->>'condicion_sql',
                    COALESCE((v_item->>'orden_visual')::SMALLINT, 1),
                    1, p_usuario
                ) ON CONFLICT (f_procedimiento_codigo, f_doc_id) DO UPDATE
                SET nivel_exigencia = EXCLUDED.nivel_exigencia,
                    condicion_sql = EXCLUDED.condicion_sql,
                    orden_visual = EXCLUDED.orden_visual,
                    estatus_registro = 1, usuario_m = p_usuario, fecha_m = clock_timestamp();
            END LOOP;
        END IF;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Documento soporte actualizado correctamente.', 'data', jsonb_build_object('doc_id', p_doc_id));

    -- 3 = BAJA LÓGICA
    ELSIF p_accion = 3 THEN
        UPDATE cxp.catalogo_documentos_soporte 
           SET estatus_registro = 0, usuario_m = p_usuario, fecha_m = clock_timestamp()
         WHERE doc_id = p_doc_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Documento soporte inactivado lógicamente.', 'data', jsonb_build_object('doc_id', p_doc_id));

    -- 4 = REACTIVAR
    ELSIF p_accion = 4 THEN
        UPDATE cxp.catalogo_documentos_soporte 
           SET estatus_registro = 1, usuario_m = p_usuario, fecha_m = clock_timestamp()
         WHERE doc_id = p_doc_id;

        RETURN jsonb_build_object('error', 0, 'mensaje', 'Documento soporte reactivado con éxito.', 'data', jsonb_build_object('doc_id', p_doc_id));
    ELSE
        RETURN jsonb_build_object('error', -1, 'mensaje', 'Acción ABC no admitida.');
    END IF;
EXCEPTION WHEN OTHERS THEN
    RETURN jsonb_build_object('error', -2, 'mensaje', SQLERRM, 'data', NULL);
END;
$$;

Motor de Validación: cxp.fn_validar_checklist_afectacion

Esta función es invocada de forma obligatoria por cxp.sp_CxpAfectacionesGasto_Workflow_V2 antes de autorizar la transición a ENVIADA. Evalúa que todos los requisitos con nivel OBLIGATORIO estén debidamente cargados en el expediente digital. 

CREATE OR REPLACE FUNCTION cxp.fn_validar_checklist_afectacion(
    p_ag_id UUID,
    p_ejercicio_fiscal INTEGER
)
RETURNS JSONB
LANGUAGE plpgsql
STABLE
SECURITY DEFINER
SET search_path = cxp, config, public
AS $$
DECLARE
    v_proc VARCHAR(40);
    v_faltantes JSONB;
    v_total_obligatorios INTEGER := 0;
    v_total_cargados INTEGER := 0;
BEGIN
    -- Obtener procedimiento de la afectación
    SELECT f_procedimiento_codigo INTO v_proc
      FROM cxp.afectaciones_gasto
     WHERE ag_id = p_ag_id AND ejercicio_fiscal = p_ejercicio_fiscal;

    IF NOT FOUND THEN
        RETURN jsonb_build_object('error', -1, 'valido', false, 'mensaje', 'Afectación de gasto no localizada.');
    END IF;

    -- Validar si requiere CFDI y no tiene cargado ninguno
    IF v_proc NOT IN ('NOMINA', 'TERCEROS_INST') THEN
        IF NOT EXISTS (SELECT 1 FROM cxp.afectaciones_gasto_cfdi WHERE f_ag_id = p_ag_id AND estatus_registro = 1) THEN
            RETURN jsonb_build_object(
                'error', -1,
                'valido', false,
                'mensaje', 'El procedimiento ' || v_proc || ' requiere obligatoriamente al menos una factura CFDI timbrada.'
            );
        END IF;
    END IF;

    -- Evaluar checklist de documentos obligatorios pendientes
    SELECT count(*),
           jsonb_agg(jsonb_build_object(
               'doc_codigo', d.doc_codigo,
               'doc_nombre', d.doc_nombre,
               'nivel', r.nivel_exigencia
           ))
      INTO v_total_obligatorios, v_faltantes
      FROM cxp.requisitos_procedimiento_soporte r
      JOIN cxp.catalogo_documentos_soporte d ON d.doc_id = r.f_doc_id
     WHERE r.f_procedimiento_codigo = v_proc
       AND r.nivel_exigencia = 'OBLIGATORIO'
       AND r.estatus_registro = 1
       AND NOT EXISTS (
           -- Verifica si el documento está adjunto en el repositorio de expedientes
           SELECT 1 FROM cxp.afectaciones_gasto_cfdi c
            WHERE c.f_ag_id = p_ag_id 
              AND (d.doc_codigo = 'DOC-CFD-XML' OR d.doc_codigo = 'DOC-VAL-SAT')
       );

    IF v_faltantes IS NOT NULL AND jsonb_array_length(v_faltantes) > 0 THEN
        RETURN jsonb_build_object(
            'error', -1,
            'valido', false,
            'mensaje', 'El expediente cuenta con documentos obligatorios pendientes de integrar.',
            'faltantes', v_faltantes
        );
    END IF;

    RETURN jsonb_build_object(
        'error', 0,
        'valido', true,
        'mensaje', 'Expediente documental íntegro y verificado correctamente.'
    );
END;
$$;

Controlador NestJS: requisitos-documentales.controller.ts

import { Controller, Get, Post, Put, Patch, Param, Body, Query, UseGuards, Req } from '@nestjs/common';
import { ApiTags, ApiOperation, ApiResponse } from '@nestjs/swagger';
import { JwtAuthGuard } from '../configuracion/auth/guards/jwt-auth.guard';
import { RolesGuard } from '../configuracion/auth/guards/roles.guard';
import { MinRol } from '../configuracion/auth/decorators/min-rol.decorator';
import { RequisitosDocumentalesService } from './requisitos-documentales.service';

@ApiTags('CxP / Catálogos / Requisitos Documentales')
@UseGuards(JwtAuthGuard, RolesGuard)
@Controller('cxp/requisitos-documentales')
export class RequisitosDocumentalesController {
  constructor(private readonly service: RequisitosDocumentalesService) {}

  @Get()
  @MinRol(4)
  @ApiOperation({ summary: 'Listar documentos soporte y matriz de checklist' })
  findAll(
    @Req() req,
    @Query('buscar') buscar?: string,
    @Query('procedimiento') procedimiento?: string,
    @Query('estatus') estatus?: number,
  ) {
    return this.service.findAll({ buscar, procedimiento, estatus: estatus ?? 1 }, req.user);
  }

  @Get(':id')
  @MinRol(4)
  @ApiOperation({ summary: 'Obtener detalle de un documento requisito' })
  findOne(@Param('id') id: string, @Req() req) {
    return this.service.findOne(Number(id), req.user);
  }

  @Get('checklist/:agId')
  @MinRol(4)
  @ApiOperation({ summary: 'Consultar estado del checklist para una afectación de gasto' })
  checkStatus(@Param('agId') agId: string, @Req() req) {
    return this.service.validarChecklist(agId, req.user);
  }

  @Post()
  @MinRol(2)
  @ApiOperation({ summary: 'Crear nuevo tipo de documento soporte' })
  @ApiResponse({ status: 201, description: 'Documento registrado con éxito.' })
  create(@Body() dto: CreateRequisitoDocumentalDto, @Req() req) {
    return this.service.create(dto, req.user);
  }

  @Put(':id')
  @MinRol(2)
  @ApiOperation({ summary: 'Actualizar documento soporte y sus reglas de procedimiento' })
  update(@Param('id') id: string, @Body() dto: UpdateRequisitoDocumentalDto, @Req() req) {
    return this.service.update(Number(id), dto, req.user);
  }

  @Patch(':id/estatus')
  @MinRol(2)
  @ApiOperation({ summary: 'Cambiar estatus de un documento soporte (baja lógica)' })
  cambiarEstatus(@Param('id') id: string, @Body('estatus') estatus: number, @Req() req) {
    return this.service.cambiarEstatus(Number(id), estatus, req.user);
  }
}
9 Reglas de Negocio y Validaciones
RN-REQ-01 · Validación Bloqueante para Envío a Revisión

El sistema impedirá ejecutar la acción ENVIAR o ENVIAR_REVISION en 05.2.1 Afectación del Gasto si existe al menos un documento con nivel OBLIGATORIO sin adjuntar en el expediente digital.

RN-REQ-02 · Unicidad del Código de Documento

El código nemotécnico (ej. DOC-CFD-XML) es estrictamente único en la tabla cxp.catalogo_documentos_soporte. Si ya cuenta con expedientes asociados, queda congelado y no se permite su eliminación física.

RN-REQ-03 · Validación Fiscal Obligatoria de CFDI

Para todos los trámites que exijan factura, la carga del XML timbrado detona la comprobación contra el webservice del SAT. El expediente marcará el requisito como válido únicamente si el UUID está vigente y el RFC del emisor no figura en listas negras (Art. 69-B del CFF).

RN-REQ-04 · Control de Vigencia en Opiniones de Cumplimiento

Las constancias de cumplimiento fiscal (SAT 32-D y SEFIPLAN) no podrán tener una fecha de expedición mayor a 30 días naturales respecto a la fecha de elaboración de la afectación. En caso de caducidad, el checklist mostrará alerta amarilla bloqueante.

RN-REQ-05 · Condicionamiento por Umbral Económico

Para compras menores o directas, si el importe solicitado supera el monto límite fijado por la Ley de Adquisiciones de Veracruz (actualmente $300,000 MXN sin IVA), la Opinión 32-D del SAT se transforma automáticamente de OPCIONAL a OBLIGATORIA.
