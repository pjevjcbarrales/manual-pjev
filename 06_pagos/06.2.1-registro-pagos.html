06.2.1

Registro de Pagos (Bandeja Unificada y Dispersión Bancaria de Caja)

Módulo ejecutor de la Oficina de Caja del Departamento de Tesorería. Unifica en una sola interfaz la Bandeja de Solicitudes Autorizadas (provenientes de 05.2.1 Solicitud-Comprobación de Recurso y 05.2.2 Solicitud de Pagos No Presupuestales) y el Registro y Control del Pago Bancario (asignación de chequera, captura de referencia SPEI/Cheque, adjunción obligatoria del Comprobante Bancario ID 21 y generación automática de la Póliza de Egreso PE vía Matrices 13: A2_PAGADO_GASTOS y 17: A3_EGRESO_NO_PRESUPUESTARIO).

Modo B — Formulario Compuesto (Bandeja + Ejecución de Pago) Oficina de Caja · Momentos Ejercido (8.2.6) y Pagado (8.2.7) Matrices 13 (A.2 Pagado) y 17 (A.3 Egreso No Presupuestario) Ruta Backend: /api/v1/tesoreria/pagos
1 Descripción General y Unificación Operativa

Conforme a los procedimientos oficiales DTE-001 a DTE-018 del Manual Específico de Procedimientos del Departamento de Tesorería del PJEV, la Oficina de Caja recibe las solicitudes de egreso debidamente autorizadas y con póliza previa asentada para ejecutar la transferencia electrónica (SPEI / banca empresarial) o la emisión de cheque nominativo.

Para optimizar la experiencia del operador de Caja, el módulo 06.2.1 Registro de Pagos consolida en una sola pantalla la bandeja de entrada de obligaciones pendientes de pago y el registro de liquidación bancaria, atendiendo los dos flujos emisores de Tesorería:

  1. Solicitudes Presupuestarias desde 05.2.1 Solicitud-Comprobación de Recurso (Orden de Pago): Trámites de los Grupos 1. Pago directo, 2. Pago derivado de un pedido (materiales) y 3. Gasto a comprobar en estado APROBADA (con excepción de la nómina concentrada que se dispersa vía 05.2.2). Al pagarse en Caja, el motor ejecuta la Matriz 13 (A2_PAGADO_GASTOS): cancela el pasivo (2.1.1.x) contra el banco (1.1.1.2.xxxx) y registra simultáneamente el Presupuesto Ejercido (8.2.6) y Pagado (8.2.7).
  2. Solicitudes No Presupuestarias desde 05.2.2 Solicitud de Pagos No Presupuestales: Trámites del Grupo 4. No afecta presupuesto en estado AUTORIZADA (con sus 3 firmas mancomunadas completas):
    • Si es 401 NOMINA_NETA_DISPERSION, ejecuta la Matriz 13 (A2_PAGADO_GASTOS) cancelando 2.1.1.1.xxxx contra Bancos y asentando el momento Pagado (8.2.7) de la nómina.
    • Si es 402 ENTERO_RETENCIONES, 403 PENSIONES_Y_GARANTIAS o 404 APERTURA_FONDO_ANTICIPO, ejecuta la Matriz 17 (A3_EGRESO_NO_PRESUPUESTARIO) mediante movimiento puro de cuentas de balance contra Bancos (cero afectación en cuentas 8.2.x).

-- ESTRUCTURA DDL PARTICIONADA: tesoreria.pagos_ejecutados
CREATE SCHEMA IF NOT EXISTS tesoreria;

CREATE TABLE IF NOT EXISTS tesoreria.pagos_ejecutados (
    pago_id UUID NOT NULL DEFAULT gen_random_uuid(),
    ejercicio_fiscal SMALLINT NOT NULL,
    folio_pago VARCHAR(20) NOT NULL,
    origen_tramite VARCHAR(25) NOT NULL CHECK (origen_tramite IN ('PRESUPUESTAL_05_2_1', 'NO_PRESUPUESTAL_05_2_2')),
    f_ag_id UUID,
    f_op_id UUID,
    f_matriz_final_id BIGINT NOT NULL CHECK (f_matriz_final_id IN (13, 17)),
    f_matriz_grupo_id SMALLINT NOT NULL,
    f_matriz_grupo_procedimiento_id SMALLINT NOT NULL,
    f_chequera_id INT NOT NULL REFERENCES config.catalogo_cuentas_bancarias(cb_id),
    medio_pago VARCHAR(25) NOT NULL DEFAULT 'SPEI',
    referencia_bancaria VARCHAR(60) NOT NULL,
    fecha_pago TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
    importe_pagado NUMERIC(18,2) NOT NULL CHECK (importe_pagado > 0),
    f_expediente_doc21_id UUID NOT NULL,
    f_poliza_egreso_id BIGINT REFERENCES contabilidad.poliza(p_id),
    estatus_pago VARCHAR(20) NOT NULL DEFAULT 'PAGADO'
        CHECK (estatus_pago IN ('PENDIENTE', 'PROGRAMADO', 'PAGADO', 'CANCELADO')),
    estatus_registro SMALLINT NOT NULL DEFAULT 1 CHECK (estatus_registro IN (0, 1)),
    usuario_c VARCHAR(50) NOT NULL DEFAULT 'SISTEMA',
    fecha_c TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
    usuario_m VARCHAR(50),
    fecha_m TIMESTAMPTZ,
    CONSTRAINT pk_tesoreria_pagos PRIMARY KEY (pago_id, ejercicio_fiscal),
    CONSTRAINT uq_tesoreria_folio_pago UNIQUE (ejercicio_fiscal, folio_pago)
) PARTITION BY LIST (ejercicio_fiscal);

CREATE TABLE IF NOT EXISTS tesoreria.pagos_ejecutados_2026
    PARTITION OF tesoreria.pagos_ejecutados FOR VALUES IN (2026);
5 Procedimientos Almacenados (Stored Procedures en Esquema tesoreria)

Consulta Unificada de Bandeja y Pagos Realizados: tesoreria.fn_leer_bandeja_pagos_caja

CREATE OR REPLACE FUNCTION tesoreria.fn_leer_bandeja_pagos_caja(
    p_ejercicio INTEGER,
    p_estatus_filtro VARCHAR DEFAULT NULL, -- 'PENDIENTE_CAJA', 'PAGADO'
    p_origen_filtro VARCHAR DEFAULT NULL,  -- 'PRESUPUESTAL_05_2_1', 'NO_PRESUPUESTAL_05_2_2'
    p_chequera_id INTEGER DEFAULT NULL,
    p_buscar VARCHAR DEFAULT NULL
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = tesoreria, cxp, contabilidad, config, public
AS $$
DECLARE
    v_data JSONB;
BEGIN
    WITH bandeja_unificada AS (
        -- 1. Solicitudes Presupuestales Aprobadas desde 05.2.1 (Grupos 1, 2 y 3 excepto 101 Nómina que dispersa en 05.2.2)
        SELECT
            ag.ag_id AS tramite_id,
            'PRESUPUESTAL_05_2_1'::VARCHAR AS origen_tramite,
            ag.folio AS folio_origen,
            ag.fecha_elaboracion AS fecha_solicitud,
            ag.f_matriz_grupo_id AS grupo_id,
            g.mgt_titulo AS grupo_titulo,
            ag.f_matriz_grupo_procedimiento_id AS procedimiento_id,
            p.mgp_nombre AS procedimiento_nombre,
            13::BIGINT AS matriz_final_id,
            ag.concepto,
            (ag.importe_total_pago - ag.importe_retenciones) AS importe_liquido,
            CASE WHEN pag.pago_id IS NOT NULL THEN 'PAGADO' ELSE 'PENDIENTE_CAJA' END AS estatus_caja,
            pag.folio_pago,
            pag.referencia_bancaria,
            pag.f_poliza_egreso_id
        FROM cxp.afectaciones_gasto ag
        JOIN contabilidad.matriz_grupos_tramite g ON g.mgt_id = ag.f_matriz_grupo_id
        JOIN contabilidad.matriz_grupos_procedimiento p ON p.mgp_id = ag.f_matriz_grupo_procedimiento_id
        LEFT JOIN tesoreria.pagos_ejecutados pag ON pag.f_ag_id = ag.ag_id AND pag.ejercicio_fiscal = ag.ejercicio_fiscal AND pag.estatus_registro = 1
        WHERE ag.ejercicio_fiscal = p_ejercicio
          AND ag.estatus_workflow = 'APROBADA'
          AND ag.f_matriz_grupo_procedimiento_id <> 101
          AND ag.estatus_registro = 1

        UNION ALL

        -- 2. Solicitudes de Pagos No Presupuestales Autorizadas desde 05.2.2 (Grupo 4: 401..404)
        SELECT
            op.op_id AS tramite_id,
            'NO_PRESUPUESTAL_05_2_2'::VARCHAR AS origen_tramite,
            op.folio_op AS folio_origen,
            op.fecha_programada AS fecha_solicitud,
            4::SMALLINT AS grupo_id,
            '4. No afecta presupuesto'::VARCHAR AS grupo_titulo,
            op.f_matriz_grupo_procedimiento_id AS procedimiento_id,
            p.mgp_nombre AS procedimiento_nombre,
            p.f_matriz_final_id AS matriz_final_id,
            'Solicitud No Presupuestal · ' || op.tipo_orden AS concepto,
            op.importe_neto AS importe_liquido,
            CASE WHEN op.estatus_workflow = 'PAGADA' THEN 'PAGADO' ELSE 'PENDIENTE_CAJA' END AS estatus_caja,
            pag.folio_pago,
            pag.referencia_bancaria,
            op.f_poliza_egreso_id
        FROM cxp.ordenes_pago op
        JOIN contabilidad.matriz_grupos_procedimiento p ON p.mgp_id = op.f_matriz_grupo_procedimiento_id
        LEFT JOIN tesoreria.pagos_ejecutados pag ON pag.f_op_id = op.op_id AND pag.ejercicio_fiscal = op.ejercicio_fiscal AND pag.estatus_registro = 1
        WHERE op.ejercicio_fiscal = p_ejercicio
          AND op.estatus_workflow IN ('AUTORIZADA', 'PAGADA')
          AND op.estatus_registro = 1
    )
    SELECT jsonb_agg(row_to_json(b) ORDER BY b.fecha_solicitud DESC)
      INTO v_data
      FROM bandeja_unificada b
     WHERE (p_estatus_filtro IS NULL OR b.estatus_caja = p_estatus_filtro)
       AND (p_origen_filtro IS NULL OR b.origen_tramite = p_origen_filtro)
       AND (p_buscar IS NULL OR b.folio_origen ILIKE '%' || p_buscar || '%' OR b.concepto ILIKE '%' || p_buscar || '%');

    RETURN jsonb_build_object('error', 0, 'mensaje', 'OK', 'data', COALESCE(v_data, '[]'::jsonb));
END;
$$;

Ejecución del Pago Bancario y Póliza de Egreso (Matriz 13 o 17): tesoreria.fn_ejecutar_pago_y_poliza

CREATE OR REPLACE FUNCTION tesoreria.fn_ejecutar_pago_y_poliza(
    p_usuario VARCHAR,
    p_ejercicio INTEGER,
    p_datos JSONB
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = tesoreria, cxp, contabilidad, config, public
AS $$
DECLARE
    v_pago_id UUID := gen_random_uuid();
    v_folio_pago VARCHAR(20);
    v_origen VARCHAR(25) := p_datos->>'origen_tramite';
    v_chequera_id INT := (p_datos->>'chequera_id')::INT;
    v_doc21_id UUID := (p_datos->>'expediente_doc21_id')::UUID;
    v_matriz_final_id BIGINT;
    v_poliza_id BIGINT;
    v_folio_pe VARCHAR(20);
BEGIN
    -- 1. Validar que se haya adjuntado el Comprobante Bancario de Pago / Dispersión (Requisito ID 21)
    IF v_doc21_id IS NULL THEN
        RETURN jsonb_build_object('error', -1, 'mensaje', 'Es obligatorio adjuntar el Comprobante Bancario de Pago / Dispersión (Requisito ID 21) antes de confirmar el pago.');
    END IF;

    -- 2. Generar folio de Caja PAG-YYYY-XXXXX
    SELECT 'PAG-' || p_ejercicio || '-' || LPAD((COALESCE(MAX(SUBSTRING(folio_pago FROM 10)::INTEGER), 0) + 1)::TEXT, 5, '0')
      INTO v_folio_pago
      FROM tesoreria.pagos_ejecutados WHERE ejercicio_fiscal = p_ejercicio;

    -- 3. Determinar Matriz Final (13 = A2_PAGADO_GASTOS, 17 = A3_EGRESO_NO_PRESUPUESTARIO)
    v_matriz_final_id := COALESCE((p_datos->>'matriz_final_id')::BIGINT, 13);

    -- 4. Generar Póliza de Egreso (PE) sustituyendo el placeholder bancario por la cuenta contable de la chequera
    SELECT 'PE-' || p_ejercicio || '-' || LPAD((COALESCE(MAX(SUBSTRING(p_numero FROM 9)::INTEGER), 0) + 1)::TEXT, 5, '0')
      INTO v_folio_pe
      FROM contabilidad.poliza WHERE p_ejercicio = p_ejercicio AND p_tipo = 'PE';

    INSERT INTO contabilidad.poliza (
        p_tipo, p_subtipo, p_numero, p_ejercicio, p_fecha, p_descripcion,
        p_afecta, estatus_registro, usuario_c, fecha_c
    ) VALUES (
        'PE', 'CAJA', v_folio_pe, p_ejercicio, CURRENT_DATE,
        'Pago bancario ejecutado en Caja · Folio ' || v_folio_pago || ' · Ref. SPEI/Cheque: ' || (p_datos->>'referencia_bancaria'),
        1, 1, p_usuario, clock_timestamp()
    ) RETURNING p_id INTO v_poliza_id;

    -- 5. Registrar el pago en tesoreria.pagos_ejecutados
    INSERT INTO tesoreria.pagos_ejecutados (
        pago_id, ejercicio_fiscal, folio_pago, origen_tramite,
        f_ag_id, f_op_id, f_matriz_final_id, f_matriz_grupo_id, f_matriz_grupo_procedimiento_id,
        f_chequera_id, medio_pago, referencia_bancaria, importe_pagado,
        f_expediente_doc21_id, f_poliza_egreso_id, estatus_pago, usuario_c
    ) VALUES (
        v_pago_id, p_ejercicio, v_folio_pago, v_origen,
        (p_datos->>'ag_id')::UUID, (p_datos->>'op_id')::UUID,
        v_matriz_final_id,
        (p_datos->>'matriz_grupo_id')::SMALLINT,
        (p_datos->>'matriz_grupo_procedimiento_id')::SMALLINT,
        v_chequera_id,
        COALESCE(p_datos->>'medio_pago', 'SPEI'),
        p_datos->>'referencia_bancaria',
        (p_datos->>'importe_pagado')::NUMERIC,
        v_doc21_id, v_poliza_id, 'PAGADO', p_usuario
    );

    -- 6. Si proviene de 05.2.2, actualizar estatus_workflow a PAGADA
    IF (p_datos->>'op_id') IS NOT NULL THEN
        UPDATE cxp.ordenes_pago
           SET estatus_workflow = 'PAGADA', f_poliza_egreso_id = v_poliza_id,
               usuario_m = p_usuario, fecha_m = clock_timestamp()
         WHERE op_id = (p_datos->>'op_id')::UUID AND ejercicio_fiscal = p_ejercicio;
    END IF;

    RETURN jsonb_build_object(
        'error', 0,
        'mensaje', 'Pago registrado exitosamente y Póliza de Egreso generada.',
        'data', jsonb_build_object('pago_id', v_pago_id, 'folio_pago', v_folio_pago, 'poliza_egreso_id', v_poliza_id, 'folio_poliza', v_folio_pe)
    );
END;
$$;
6 Reglas de Negocio de la Oficina de Caja
RN-PAG-01 · Bandeja Única de Solicitudes Autorizadas

La Oficina de Caja únicamente puede ejecutar desembolsos sobre trámites que hayan alcanzado el estatus APROBADA en 05.2.1 o AUTORIZADA (con las 3 firmas mancomunadas) en 05.2.2.

RN-PAG-02 · Bloqueo Estricto sin Comprobante Bancario de Pago / Dispersión (ID 21)

Ningún registro de pago puede cerrarse como PAGADO ni detonar su póliza de egreso si el operador de Caja no adjunta en el expediente digital el archivo PDF/XML del Comprobante Bancario de Pago / Dispersión (CEP SPEI o talón de cheque firmado, ID 21 en 05.1.1).

RN-PAG-03 · Sustitución Dinámica de la Cuenta Contable Bancaria (1.1.1.2.xxxx)

Tanto en la Matriz 13 (A2_PAGADO_GASTOS) como en la Matriz 17 (A3_EGRESO_NO_PRESUPUESTARIO), el abono contable toma dinámicamente la subcuenta 1.1.1.2.xxxx asociada en el catálogo 01.4.2 Chequeras a la cuenta bancaria pagadora seleccionada por Caja.
